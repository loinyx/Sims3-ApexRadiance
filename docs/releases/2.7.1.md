# Apex Radiance 2.7.1

Published 2026-10-06 · tag [`v2.7.1`](https://github.com/loinyx/Sims3-ApexRadiance/releases/tag/v2.7.1) · asset `ApexRadiance.asi`.

## Highlights

The features and fixes first prepared for 2.7.0, included here after an antivirus false positive prevented that build from being published.

## Fixes

- **Antivirus:** some antivirus programs that use BitDefender's engine flagged the original 2.7.0 build by mistake. This release includes those features and fixes with the detection addressed before publication.
- **Color tab:** the Color settings and filters show again. In 2.7.0 they did nothing while Ambient Occlusion, Edge
  Smoothing or Depth Blur was on.
- **dxwrapper:** with dxwrapper instead of DXVK, the game no longer crashes after the first loading screen. There, lamp
  switches change room by room instead of all at once.
- **Color on other game versions:** Color, Ambient Occlusion and Edge Smoothing no longer stay off on game versions where
  Apex cannot read the loading screen.

## Changes

- `ApexRadiance.asi` 2.7.0 was flagged by 10 of 71 engines on VirusTotal: BitDefender's generic `Gen:Variant.Fragtor`
  (and the engines built on it: ALYac, Arcabit, Emsisoft, eScan, GData, VIPRE), CrowdStrike (grayware), CTX and Cynet.
  2.6.0 had 2 of 70. Two test builds told the cause apart:
  - without the registry scan of the [Vulkan driver guard](../features/performance/vulkan-driver-guard.md) (AMD's layer
    variable is now set by its known name, `DISABLE_LAYER_AMD_SWITCHABLE_GRAPHICS_1`): still flagged;
  - and with `d3dcompiler_47.dll` linked normally instead of delay-loaded: 2 detections, as 2.6.0. 2.7.1 ships this one.
- The shader cache on disk stays ([architecture.md](../architecture.md)): later starts still create Apex's shaders
  without compiling them; the compiler DLL is mapped at start again, as in 2.6.0.
- AtriumHold patches the texture locks (`LockRect`/`UnlockRect`) only when they are in a `d3d9.dll` (DXVK, Windows'
  own): a player's game with dxwrapper crashed after the first loading screen with 2.7.0 and not with this rule. Elsewhere
  lamp switches all at once and an atrium's stories waiting for each other are off.
- The world gate of the screen effects (`WorldSession::InWorld`) never keeps them off for good: a game build where the
  loading window getter or the world manager cannot be read no longer counts as "still loading".
- Picture's scene copy waits for the post-scene effects of the frame (`PostScene::EffectsPending`): since it counted a
  depth test with ALWAYS and no depth write as the end of the scene (pie menu fix of 2.7.0), it copied before ambient
  occlusion, edge smoothing and Depth Blur, which still count such draws as scene; every pixel they changed then differed
  from the copy and its UI mask kept it as the game drew it.
- Two builds again: the published `PublicApexRadiance.asi` without the developer tools (Frame Profiler, Frame Capture,
  bloom probe; developer mode never on) and the maintainer's `ReleaseApexRadiance.asi` with them.
- The in-game What's new of 2.7.1 lists 2.7.0's lines with the antivirus fix.

## Upgrade notes

Close the game, then replace `ApexRadiance.asi` in `The Sims 3\Game\Bin\`. Your settings are kept.
