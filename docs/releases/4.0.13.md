# Apex Radiance 4.0.13

2026-11-20 · [v4.0.13](https://github.com/loinyx/Sims3-ApexRadiance/releases/tag/v4.0.13) · ApexRadianceSetup.exe, Apex-Radiance-4.0.13-Manual-install.zip

## Highlights

**4K videos, and ReShade looks that leave Sims' hair alone.** The recorder records up to 4K at 60 fps with the colour
conversion on the GPU, and each Looks shader can stay off Sims' hair, so outline shaders such as Comic no longer draw
lines inside hairstyles.

## Shaders

- **ReShade Effect Shader Toggler.** A REST `.ini` decides where each shader runs: before or after a matched game draw,
  or at a render-target change, by the CRC32 of the game's shader bytecode, with REST's groups, technique lists and
  resolution check. Shaders that no group takes run at the end of the frame as before.
- **On Sims' hair.** Each shader of a look has a slider for how much of it Sims' hair takes (100% by default). Below
  100%, the picture from before the shader is put back where the Sim Occlusion hair mask finds hair: opaque and
  alpha-tested hair whose depth is the scene's, and blended strands in front of the scene (1/16 coverage or more counts
  as all hair, because the mask keeps only the last blended layer's alpha). Needs Ambient Occlusion on.

## Video

- **4K.** Size has 720p, 1080p, 1440p and 4K (balanced 52 Mbit/s at 30 fps, x1.6 at 60).
- **NV12 made on the GPU.** One pixel shader pass turns the frame into NV12 (BT.709, 16-235) before the read back: 1.5
  bytes a pixel instead of 4 (12 MB a 4K frame) and no colour conversion on the CPU. The mouse pointer is blended into
  the NV12 bytes. The encoder's input buffers are reused instead of allocated for every frame.
- **Even frame rate.** One frame a period, stamped on the period's grid. A frame taken up to 1/8 period early let the
  next frame through as well, so a 30 fps video at a 75 fps game held about 40 frames a second with repeated
  timestamps. Frames are copied only once the encoder runs (about 2 s after the key), and the ring has 4 GPU slots.

## Performance

- **Faster text lookups** (rodneypantonial, #140): an in-memory index of the game's loaded string tables answers name
  lookups in one probe instead of walking every table; off by default, Experimental, under System > Performance > Files
  and objects.

## Bug reports

- **A session that did not close.** A GPU hang freezes the game without an exception, so it left no crash report. The
  next start now logs the last session's last steps, the graphics driver's events and the RTX Remix bridge's errors
  ([architecture](../architecture.md), *Session trace*).

## Fixes

- **HEVC with the crash-safe format.** Media Foundation's fragmented MP4 sink refuses HEVC at any size, so HEVC never
  recorded with the default crash-safe MP4; HEVC is now written as a plain MP4.
- **RTX Remix bridge** (rodneypantonial, #126): a state block keeps the FVF and the vertex declaration while it records,
  as upstream dxvk-remix #170; `SetFVF(0)` leaves the state as it is.

## Testing

In-game runner under the RTX Remix bridge (Steam 1.67.2, 3840x2160): a 1080p 30 fps video's colours match a screenshot
of the same view; 4K 60 fps HEVC, 1079 frames over 18.4 s with none dropped; 4K 60 fps H.264 recorded; Comic.fx in CAS
at On Sims' hair 0% leaves the hairstyle without lines. An offline Media Foundation probe: HEVC fails `BeginWriting`
(`0xC00D36B4`) with the fragmented MP4 sink at 1080p and 4K, with NV12 or RGB32 input, and succeeds with the plain
MP4 sink.

## Known limitations

- HEVC videos are not crash-safe.
- A 4K 60 fps video can miss single frames when the game's own frames do not land in a period (23 gaps of up to 50 ms
  in 18.4 s at a 70 fps game).
- The session report reads the RTX Remix bridge's log only when it has not been written over by the next start.
