# 3D CUBE LUT test

Status: local test build, based on 2.11.1. Not installed or released.

The existing Color > Filters > LUT card lists PNG strips and 3D `.cube` files in
`Documents\Electronic Arts\The Sims 3\Apex Radiance\LUTs`. The selected filename,
amount, filter switch and shortcut continue to use the existing settings.

The parser accepts sizes 2 through 65, TITLE/comments, UTF-8 BOM, DOMAIN_MIN/MAX and
Resolve LUT_3D_INPUT_RANGE. RGB samples retain float32 precision, including values
outside 0–1. Red changes fastest, then green, then blue. Unsupported 1D/combined
files and malformed tables are rejected; details go to the log. Files are capped
at 32 MiB. The PNG decoder and lookup calculations remain unchanged.

A power-of-two float32 texture stores the selected table, with explicit trilinear
interpolation. This avoids requiring float texture filtering. Maximum padded GPU
storage is 8 MiB for a 65-cell table; loading temporarily holds its CPU samples.
Loading happens on filename change or device reset, not every frame. The main
SDR pipeline still applies its existing gamma conversion and output clipping.
Camera/log transforms are not automatically converted into display LUTs.

Validation: Win32 Release public-flavor compilation, native D3D9 HAL shader
creation, parser checks and analytic pixel readbacks, including actual packed
dimensions and clamping outside custom input domains. Disassembly confirms a
dynamic branch around CUBE taps, so PNG files skip them. The supplied Resolve LUT
parsed as 33 cells and 35,937 RGB entries. Menu audit adds no new missing UI
translations; the existing developer-only findings remain. New help/error keys
are present in all 21 languages.

Pending: gameplay with real LUTs, device-reset/menu selection checks in game,
visual PNG comparison, DXVK/Proton, and hardware without float32 texture support.
No performance or universal visual parity claim is made.
