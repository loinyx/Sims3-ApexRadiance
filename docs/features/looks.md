# Looks

Gives the game a ReShade look: Apex runs a ReShade or GShade preset (.ini) on the game's picture with the same shader
maths, without ReShade or GShade installed. The player picks a look, sets its strength and whether the interface stays without it,
and can switch, reorder and tune the preset's shaders, then save the result as a look of their own.

## The problem

Many players dress The Sims 3 with ReShade or GShade presets. Those injectors grade the finished frame, so the game's
menus and text get the look too, they cost a second Direct3D hook chain, and they do not see Apex's own picture steps.
A preset is a plain .ini that names techniques of .fx effect files and their values; the effects themselves are
written for ReShade's runtime, not for shader model 3.0 as the game uses it.

## How Apex Radiance solves it

The shaders a look uses are ported once to ps_3_0 with their maths unchanged (`third_party/reshade_shaders`, see
[Shader sources and licences](#shader-sources-and-licences)); a generated header embeds them in the ASI and they are compiled by Apex's shader cache the first time the feature is
turned on. At run time Apex reads the chosen preset, runs its enabled techniques in the preset's `TechniqueSorting`
order with its values, and blends the result over the picture by *Strength*.

1. The look is a reference to a source and a relative path: `looks:<file>` (Apex Radiance\Looks\) or `gshade:<file>`
   (GShade's folder, recursive). Apex never stores an absolute path and never writes in GShade's folder. Earlier builds
   also shipped five built-in looks (`apex:<name>`); a saved `apex:` reference now loads as no look chosen.
2. The run list is the preset's enabled techniques, plus shaders added here (at the end), in the player's own order
   when one was set. A technique runs from a built-in port or, when Apex has none, from the player's Shaders folder
   ([Your shaders](#your-shaders)); the others stay in the list as amber rows with what is wrong. A GShade preset can name a file that no
   pack publishes under that name (MXAO in "MXAO 4.0.2 EX.fx"): when that file is nowhere, the technique runs from a
   pack file that has it (`qUINT_mxao.fx`), chosen by `Looks::Packs::FileForTechnique`: a downloaded pack first, then a
   file whose name shares the original's first word ("mxao"), then ReShade's list order. Its values still come from the
   look's own section (`[MXAO 4.0.2 EX.fx]`), and an exported preset names the pack of that file.
3. Each shader's values are the .ini's (or the .fx default when the .ini has none) unless edited here.
4. The passes run in Apex's post-scene chain: after Apex's Color (order 45) or before it (35). With *Interface without
   shaders* on (the default) they run right after the game's bloom, before the interface and the game's colour pass,
   so menus, panels and loading screens keep their own colours; with it off they run at the end of the frame, like
   GShade, over the interface too. Both give the world the same colours ([Technical reference](#technical-reference)).
   Shaders that read depth always run at the scene boundary, never over the interface.
5. Holding the card's eye, the picture-compare key (B) or the menu's eye in the Color header skips the look for as
   long as it is held; *Compare with the game* turns it off with the other Apex effects, and so do *Turn off Apex* and
   the Overview's *All effects* (both turn it back on with the rest).

## Your shaders

The player's own ReShade or GShade effects run too. They go in `Documents\Electronic Arts\The Sims 3\Apex Radiance\Shaders\`,
laid out as ReShade lays out `reshade-shaders`: `.fx` and `.fxh` files in `Shaders\` (subfolders allowed, three deep) or
directly in the folder, textures in `Textures\`. *Add .fx files…* copies picked files there (off the render thread):
`.fx` and `.fxh` into `Shaders\`, images (`.png`, `.jpg`, `.jpeg`, `.bmp`, `.dds`) into `Textures\`, anything else is
refused; the same file is reused and a different file of that name gets a numbered name ("Name-1.fx").

- When Looks is turned on, every `.fx` compiles on a background thread with ReShade's own effect compiler (vendored,
  BSD 3-Clause) and its shader model 3.0 code generator, the path ReShade itself uses on Direct3D 9, for the picture's
  size. Shaders appear in the menu as they compile; unchanged files are not compiled again in the session, and the
  compiled shaders are kept in `Shaders\.cache\` (one file per effect and picture size), so the next session reads
  them instead of compiling (see [Performance and memory](#performance-and-memory)).
- A preset that names a technique of those files runs it in its place in the run list, with the .ini's values, beside the
  built-in ports. A built-in port of the same technique and file wins.
- What runs: vertex and pixel shader passes with their render targets (up to 4 per pass), blending, stencil, sRGB
  reads and writes, mipmaps, clears, texture files, ReShade's uniform sources (timer, frame time, frame count, random,
  ping-pong, date, depth ready; keys and mouse stay 0), the `COLOR` and `DEPTH` textures (depth from the scene, so depth
  shaders run on the world, never over the interface).
- Direct3D 9 fallbacks before a shader is refused: formats D3D9 does not have are lowered to the nearest one (RG8 to
  RGBA8, RG11B10F to RGBA16F, integer textures to 32-bit float, 1D to 2D); other compile flags are tried when the first
  set fails.
- What does not run: compute shaders, more than 4 render targets in one pass, 3D render targets, integer bitwise
  operators, other texture semantics; the log and the developer build's *Live counters* give the reason. A missing
  texture file leaves that texture black and the effect runs, as in ReShade (a note says which file).
- As ReShade 6.7.3 runs them (4.0.4): compiled at optimisation level 1 first (`__RESHADE_PERFORMANCE_MODE__` 0), the
  other D3DCompile flag sets only when that fails; `BUFFER_COLOR_FORMAT` 87; a definition `FOO=` is 1; includes found in
  every subfolder of the Shaders folder and of each pack's (`Shaders\**`); timer and frametime from a fine clock; a bool
  `framecount` true on even frames; `pingpong` with ReShade's step range, smoothing and 0.05 minimum; each pass sets
  two-sided stencil off, solid fill, no dither and the last pixel on; anisotropic samplers at 16; sRGB reads and writes on
  8-bit textures only; a new texture's mips cleared with it; every sampler bound to the vertex stages 0..3 too (saved and
  put back); `key`, `mousebutton` (held, toggle, press), `mousepoint` and `mousedelta` while the game has the focus; a
  ReShade.ini or GShade.ini beside the game's exe gives its `[GENERAL] PreprocessorDefinitions` (the look's win; its
  `RESHADE_DEPTH_*` are not taken, Apex knows this game's depth); a shader listed before a depth shader runs before it.
  A texture (no semantic) that another running effect already made under the same name is that one, with its size and
  contents; `mousewheel` (step, min, max) and `overlay_open` (the Apex menu); `__VENDOR__` / `__DEVICE__` of the game's
  graphics card. Not taken: `pooled` textures (each effect keeps its own: more memory, the same pictures).
- Limits: 2 MB per .fx or included file, 64 includes, 16 MB of preprocessed code, 64 MB per texture file, 64 textures and
  256 MB of textures per effect, 384 MB for every user effect running, 64 passes per technique, 256 user passes per frame,
  two minutes of compile time per file. Includes and textures must stay inside the Shaders folder (`..` and absolute
  paths are refused). A file that crashes or hangs the compiler is refused, not the game.

Measured offline over six common packs (AlucardDH, SweetFX, reshade-shaders slim and legacy, prod80, FXShaders): 146 of
148 techniques run on Direct3D 9 ([history](../history/looks-fx-loading.md)).

Compared with real ReShade 6.7.3 (its ReShade32.dll on the same Direct3D 9 device, 4.0.4): over 12 packs (Ann-ReShade,
AstrayFX, BFBFX, Depth3D, dh-reshade-shaders, FGFX, GShade-Shaders, prod80, qUINT, ReShade legacy and standard effects,
SweetFX), every one of the 219 techniques both run gives the same pixels to the bit on a gradient, noise and three game
screenshots at 1920x1080 (time sources pinned to the same values; no depth on either side, so depth effects are compared
on an empty depth buffer only). Not compared: 5 that need integer bitwise operations or fail in ReShade's compiler too,
and GShade's MotionFocus, which ReShade 6.7.3 cannot compile on Direct3D 9 (Apex runs it with flow control kept).
Texture images are resized as ReShade resizes them (`third_party/stb`, stb_image_resize2 at ReShade's pinned commit).

## Parameters and quality settings

Each parameter of an open shader gets the control ReShade's own overlay would give it, from the .fx annotations
(`LooksControlOf` in `features/looks_shaders.h`; the 17 ports from their parameter table, which has the kind, the
components, the range and the combo items):

| In the .fx | Control |
|---|---|
| `bool` | Switch, in a row as tall as the slider rows around it (`SetNextRowMinHeight`) |
| `ui_type = "slider"` or `"drag"` (one component) | Slider, the .ini's value as an amber tick, integers rounded (to `ui_step` when it is larger than 1) |
| `"combo"`, `"radio"`, `"list"` with `ui_items` (split on `\0` as ReShade does) | A dropdown, 220 units (under the label below 360 units) |
| `ui_type = "color"`, float3 / float4 | `ColorRow`: a swatch with its 0..255 values; the swatch opens a colour picker (an alpha bar for float4) |
| float2..4, int2..4 that are not a colour | One row of number fields, one per component, named by a "(a, b)" or "(a/b)" list at the end of the label, R G B for a label starting with RGB, else X Y Z W; each keeps the author's range; under the label, wrapping, when narrow |
| `"input"` or no `ui_type` | A number field, clamped to `ui_min` / `ui_max` when the .fx gives them |
| `ui_category` (`ui_category_closed`) | A quiet group label with a chevron where the category changes, as ReShade groups them (collapsed when the author asked) |
| `ui_tooltip` | The row's description |
| `ui_text` (also a `"radio"` without items, used as a label) | A muted text block before the row |
| `hidden = true`, `source = ...`, arrays, matrices | Not shown; hidden ones still take the .ini's value |

Labels, descriptions and choices are the author's text, shown as written. Measured over the 131 `.fx` files of six
common packs (`tools/looks_fx_check --params`): 1310 uniforms, 1245 shown, 65 set by ReShade, none without a control.

**Quality settings** are ReShade's preprocessor definitions. The look's `PreprocessorDefinitions=` line (all its
effects) and an effect section's own `PreprocessorDefinitions=` (ReShade 6 keeps an effect's edited ones there, the
later winning) are passed to ReShade's preprocessor before each of the player's or a pack's .fx, so a look compiles as
in ReShade. An open shader from a .fx lists, under Advanced *Quality settings (<n>)*, the definitions the effect tests
with `#ifdef` / `#ifndef` (ReShade's own list: not `BUFFER_*`, `RESHADE_*`, names starting with `_`, or include guards),
each with the look's value (else the .fx's own `#define`) as its default: 0 or 1 a switch; an integer that the effect's
`#if` / `#elif` lines compare with at most 8 values ("0 to 5") a 120-unit dropdown (only the values that compile
here, see below); any other number or text a field that applies
when it is left. A change compiles that effect again on the background compile thread; the old one keeps running and
"Compiling the new settings…" shows beside *Put back the look's settings* until the new one replaces it. Values that cannot run here are not offered: while a file's settings show, the next scan
(`Looks::Fx::WantProbe`) compiles it once more for each other value of each switch or short-list setting, the others
as they are, and `ProbedValues` keeps the ones that fail; a switch whose other value fails, or a list left with only
its current value, is not listed, and the title counts the rest. FXAA's platform switches go this way (of 14 values
tested, 9 fail: FXAA_HLSL_4 / _5, the GLSL, PS3, 360 and console paths, FXAA_DISCARD, FXAA_GATHER4_ALPHA; about 0.6 s on
the scan thread, again only when the file or its settings change). `tools/looks_fx_check --probe` checks it. When the file no longer compiles with an edited setting (FXAA's `FXAA_HLSL_4` asks for Direct3D 10), the
settings go back to the last ones it ran with (`g_goodDefs`; none edited when it never ran with any) and it compiles
again (a file that failed matches only the exact definitions it failed with, `MacrosMatch`); a note under the list says "<shader> doesn't run with that setting in The Sims 3, so it went back to the last one that worked". An effect
keeps the definitions it was compiled with (`Effect::compiledWith`); `Looks::Fx::MacrosMatch` counts those as a match,
so a look definition that the .fx overrides with its own `#define` does not compile it again at every scan. Edits are
undoable, kept per .fx file in `defines`, written by *Save as a new look…* into the effect's section
(`PreprocessorDefinitions=`) and carried by Apex presets in `[patches.Looks]`. The built-in ports have none. Measured
over the same packs: 169 definitions in 52 files (94 switches, 4 segmented, 46 number fields, 25 text fields).

## Shader packs

The 45 packs of ReShade's official list (`EffectPackages.ini` of crosire/reshade-shaders, the list ReShade's installer
shows) can be downloaded from *Get more packs* on the Installed shaders tab, or from *Add shaders* as one of their shaders is added. Apex carries none of them: each comes from its author's GitHub,
under its author's licence, when the player clicks Download.

- The index (`features/looks_packs_index.h`, generated by `tools/looks_packs_index.py`) holds names only: each pack's
  name, author, repository, branch, licence label, approximate size, and its `.fx` files with their techniques. It
  lists the packs and tells which pack has a missing `.fx` (the technique first, then the earliest pack on ReShade's
  list). ReShade's list is read again when the player first clicks Download in a session; a pack it no longer has
  stays listed once downloaded.
- Downloads run on a worker thread, one pack at a time: HTTPS to GitHub hosts only (every redirect checked), the zip of
  the pack's branch, at most 64 MB, 5000 files and 128 MB kept, only `.fx`, `.fxh` and images, no unsafe paths. A pack
  goes to `Shaders\Packs\<pack>\Shaders\` and `Textures\`; an update replaces it only once the new files are all
  written. ReShade's standard effects (`ReShade.fxh`, which most packs include) download first when missing.
- A downloaded pack's `.fx` compiles only when a look names it or the player adds one of its shaders. What the others
  run is read from the check cache (`Shaders\.cache\checked.txt`: per file, its size and time and which techniques run
  here); while *Add shaders* is open, the files it does not know (new or changed) are
  checked once in the background, one at a time at low priority, and let go, so "<x> of <y> run here" and the list fill
  in. A look that wants a file comes first. Its includes and textures are searched in the pack, the player's folder, then every
  other pack (the standard effects first), as in one `reshade-shaders` folder. A file of the same name in the
  player's own folder wins.
- A downloaded pack is never changed or removed except by *Update* or *Remove*. A pack gone from GitHub fails with
  "This pack is no longer on GitHub" and the queue goes on; "GitHub is busy; try again in a few minutes" for a rate
  limit; "No connection to GitHub" offline.

## Shader sources and licences

Each port is the author's `.fx` from the author's public repository, with only mechanical ps_3_0 changes (uniforms in
constant registers, includes and techniques replaced, ReShade's sampler names mapped to Apex's). Each was checked
against its original compiled by ReShade's compiler: within 1 level of 255 on four pictures and four value sets
(`tools/looks_fx_check --compare`, [history](../history/looks-shader-packs.md)). The table of files,
repositories, authors and licences, and the licence texts, are in
[third_party/reshade_shaders/LICENSES.md](../../third_party/reshade_shaders/LICENSES.md); Settings > About shows the
texts under *Third-party licenses*, with the licence of ReShade's effect compiler (crosire, BSD 3-Clause,
[third_party/reshadefx/LICENSE.md](../../third_party/reshadefx/LICENSE.md)), which compiles the player's own .fx files.

## Presets

`[patches.Looks]` is the Shaders part (bit 10). A preset also stores `packs`, the names of the packs the look's run list
uses (`Looks::NeededPacks`: a downloaded pack's file, or the pack of ReShade's list that has a missing file, read from the
look's .ini and the folders, so it is right while Shaders is off); importing
a preset with the Shaders part offers those not downloaded in the same note card as an imported look ("Imported:
<preset>", "This preset uses shaders from <packs>, which you don't have yet"), on the Presets page and on Shaders >
Look. A `[patches.Looks]` table without `packs` was written by a 3.3.0 development build, whose Color part carried
it: it shows as the Shaders part and is applied when Color or Shaders is. Exporting a preset whose Shaders part has a `looks:` or `gshade:` look adds
the .ini to the ZIP as `Looks/<file name>` (stored entries and checksums, as for `LUTs/`) and stores the reference as
`looks:<file name>`; the export is a ZIP whenever a LUT or a look file goes with it. Import writes the file into
Apex Radiance\Looks\: identical bytes reuse the existing file, a different file of that name gets a numbered name and
the reference follows it; a package whose file is not the one its profile names, or that has a path in the name, is
refused. When the look uses the player's own files, the export offers *Include my
own .fx files* (unchecked): the .fx files the look names that are in Shaders\Shaders, the .fxh they `#include` and the
textures they name (`source = "..."`) in Shaders\Textures go in as `Shaders/Shaders/<name>` and
`Shaders/Textures/<name>` (at most 64 files, 2 MB per .fx/.fxh, 16 MB per texture; packs' files never). Import writes
them into the player's Shaders folder with the same rules (identical bytes reused, a different file keeps its place and
the copy gets a numbered name, which the look then does not use); names with a folder or another extension are refused.

## Compatibility and interactions

- **Color (Picture):** *Order* puts the look after or before Apex's Color. A LUT that copies the same look grades the
  picture twice; the look card's amber row says so and offers to turn the LUT off.
- **Ambient Occlusion, Depth Blur, Edge Smoothing:** a look's shader doing the same job doubles the effect; its row says
  so and offers to turn Apex's off.
- **Captures:** `%PresetName%` in file names and *Save the look's preset too* use the look's .ini; *Look only while a
  look is on* captures the frame before the look (`ApexCapture::BeforeLook`).
- **ReShade or GShade installed too:** both grade the picture; turn one off.
- **RTX Remix bridge:** the device state the passes change is put back by hand, and by a `D3DSBT_ALL` state block when a
  getter the bridge does not answer failed.

## Limitations

- Built in: the 17 ported shaders (Levels, Technicolor2, RetroTint, DPX, AdaptiveSharpen, Vibrance, Tint (Sepia),
  Tonemap, Colourfulness, LumaSharpen, CAS, Curves, Vignette, Technicolor, HDR (FakeHDR), PD80 Selective Color,
  LiftGammaGain); other techniques run from the player's Shaders folder or stay in the list as amber rows.
- The player's effects compile for the picture's size (`BUFFER_WIDTH` is a constant in ReShade): after a resolution
  change they wait while the folder compiles again. A changed `.fxh` alone is noticed by *Check again*, not by the
  automatic scan.
- The built-in ports have no quality settings: they are compiled with the .fx defaults. A definition that only an
  `#if` line uses (no `#ifdef` / `#ifndef`) is applied but not listed, as in ReShade.
- A definition change that adds or removes uniforms puts that shader's edited values back to the .ini's.
- Downloaded packs compile for the picture's size like the player's files. The check cache knows only a file's own
  size and time: a pack's changed `.fxh` alone shows in "<x> of <y> run here" after *Check again*.
- *Reset all settings* resets the switch, Strength, Interface without shaders and Order; the chosen look and its edits stay.

## Technical reference

- Post-scene order 45 (after Picture) or 35 (before). Run points (`WhereOf` in `patches/looks_patch.cpp`): shaders
  that read depth at the scene boundary, under the game's colour curve like the World run (4.0.4: before, MXAO's shade
  came out about half as strong in mid and bright tones and SMAA found fewer dark edges than in ReShade); with *Interface without shaders* off, the rest at the end of the frame from
  `endSceneBeforeOverlay` on the back buffer; with it on (`World`), right after the boundary's own draw when that draw
  is the game's bloom (a full-screen two-triangle strip), before the next back-buffer draw (the UI) or the first copy
  of the game's colour pass, else at the boundary.
- The game's colour pass: after its UI the game copies the back buffer in 256x256 tiles and draws each back with
  `x (1 + c) / (x + c)`, c = 0.4 in every capture (read from PS c0 at the second tile; `PostScene::ColourCurveLastFrame`).
  ReShade shaders are made for the picture after that curve, so the World run first applies it in the runner's copy
  pass (`Frame::gameCurve`, PS c3) and writes the result back through its inverse `c x / (1 + c - x)`: after the
  game's curve the world shows the look's own pixels, the same as at the end of the frame. The look never runs inside
  the colour pass ([history](../history/looks-fx-loading.md#2026-11-15-world-only-and-the-games-colour-pass)).
- Each run copies the target to an A8R8G8B8 ping texture, runs the steps through ping-pong targets (AdaptiveSharpen
  adds a G16R16F target), and writes RGB back, blended by *Strength*; the last step draws straight into an 8-bit target
  at full strength.
- Constants: c0 `1/W, 1/H, W, H`, c1 pass data, c2 depth far plane, c3 the copy pass's curve; parameters from c8 (PD80 Selective Color uses up to
  c63). ReShade's uniform sources timer, frametime, framecount and random are filled once per frame.
- The player's effects: compiled by `third_party/reshadefx` (shader model 3.0) and `D3DCompile`; each runs in place on
  the ping texture as ReShade runs it on the back buffer (uniforms from PS/VS `c0`, `__TEXEL_SIZE__` at VS `c255`).
  Textures and render targets are released before a device Reset and created again at the next run. Every .fx is
  compiled with `RESHADE_DEPTH_INPUT_IS_REVERSED=0` after the look's own definitions (a look that sets it keeps its
  value): the scene depth is 0 near to 1 far, while `ReShade.fxh` and `qUINT_common.fxh` default to reversed
  ([history](../history/looks-fx-loading.md#2026-11-15-reshade-depth-is-not-reversed)).
- Device state: around each run point (`SavedState` in `patches/looks_patch.cpp`) Apex reads and puts back by hand the
  state the passes change, listed in `Looks::kSavedRenderStates` / `kSavedSamplerStates` (`features/looks_runner.h`):
  for the built-in passes 16 render states, 8 sampler states of s0 to s5 and the PS constants up to the highest register
  their parameters use (`Looks::PsConstsUsed`); with a player's effect every listed state, 16 samplers, PS c0 to c223,
  VS c0 to c255 and render targets 1 to 3; always the shaders, declaration or FVF, stream 0, render target 0,
  depth-stencil, viewport and scissor. `tools/looks_fx_check --state` checks that nothing else changes. A `D3DSBT_ALL`
  state block is captured and applied only when a getter failed.
- Shader registration is lazy (`RegisterShaders` on the first Install); the cache compiles them on a new worker run.
- Everything read from files is bounded: a preset over 1 MB is refused, at most 256 techniques are kept, at most 2000
  files are listed per source, and non-finite values are ignored.

## Performance and memory

- **Off or never used:** nothing is hooked and nothing runs per frame; the shaders are registered and the Shaders folder
  scanned at the first Install. There is no folder polling: the folder is read when Looks is turned on, by *Check
  again*, after *Add .fx files…*, a download or a removal, when a look wants a pack file and after a picture size change.
- **Per frame with a look on:** at most three run points; each reads and puts back only the listed state (no state block
  when every getter answers) and, while no shader is skipped, allocates nothing (the step list and the status line keep
  their memory).
  *Strength* 0 skips the chain (the write-back's blend factor is 0, so the picture is the game's to the bit).
  A shader is never skipped for having neutral values: the ports' maths are not exact identities.
- **Compiling:** the player's and the wanted packs' effects compile once per session and picture size; D3DCompile's
  results are kept in `Shaders\.cache\` keyed by every entry point's generated HLSL (the preprocessed source with its
  includes and macros), the target, D3DCompiler's version and the look's definitions, so a changed `.fx`, `.fxh` or
  picture size compiles again and anything else is read back. Each set of definitions has its own cache file, so going
  back to quality settings used before reads them instead of compiling.
- **Browsing packs:** *Add shaders* and *Get more packs* compile nothing and keep no pack effect in memory (the check
  cache above); the background check of unknown files lets each effect go.
- **Address space:** D3DCompile's own heap takes up to about 420 MB while a few large pack shaders compile; the
  process heap then grew new segments in the middle of the largest free block and kept them there (offline: 1202 MB to
  794 MB after the first check of six packs). The process heap grows by 40 MB once before the first compile, which keeps
  them at the bottom (1202 MB to 1154 MB, the same bytecode). Background checks pause while less than 512 MB is free.
- **GPU memory:** an effect instance not run for 120 frames (switched off, out of the look) gives its render targets
  back; the 384 MB cap counts only the ones in use. The scene depth (DepthBlur's INTZ copy) is asked for only while a
  shader that is on reads it.
- **Menu:** *Add shaders* works out its filtered list only when the search, Kind, the sources or the language
  change, and lays out only the rows in view (the others take their measured height).

Measurements: [history/looks-fx-loading.md](../history/looks-fx-loading.md#2026-11-14-performance-and-memory-pass), [history/looks-shader-packs.md](../history/looks-shader-packs.md#2026-11-14-browsing-packs-compiles-nothing).

## Rejected approaches

- **A converted-effect package (`GShadeLooks.pak`)** with every GShade .fx converted offline: large, unlicensed for
  most effects, and it tied the feature to one GShade release. Only hand-checked ports with a licence remain.
- **Reading shaders from a GShade installation** at build or run time: the build depended on a local install and the
  result on its version; the ports and their licences now live in `third_party/reshade_shaders`.
- **A two-pane menu** (run list beside a values pane): it did not fit the 400-unit minimum width or text size 200%;
  each shader's values now open under its row.
- **Clarity, HighPassSharp and FilmicPass ports:** removed, no licence in their sources.
- **Ports of GShade's copies of the shaders:** GShade edited the maths, names and notices; the ports follow the
  authors' repositories instead.
