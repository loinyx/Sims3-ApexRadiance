# S0-08: window light laws (types 7, 8)

- Status: done (static; tunable values open)
- Commits: see `git log gi/s0-08` (`lighting: window light law, sun patch and curtain dimmer`)
- Deliverable: `docs/engine/light-objects-and-rigs.md`, section "Window lights (types 7, 8): the daylight law".
- Acceptance: a law precise enough to code as an emitter, unverified parts marked. Met: every term is written out with
  its address; only the run-time values of eight tunables are open.

## Findings

- **Shape** (verified): not an area integral. The sky share is a point at the window centre with a linear range R,
  a near-plane fade, a vertical sky/ground blend and the window's area as a scale. The sun share is a projected patch:
  the ray from the texel to the sun must cross the window rectangle (soft mask), within 8 m (rectangle) or 64 m (circle).
  Both use the wrapped `N · L`. Output = dimmer × (sun + sky).
- **Sky link** (verified): sun direction and colour from `lightMgr+0x140` / `+0x130`; sky colour from one of two
  weather curves picked by the side the sun is on; tint from the window record. The sky update runs from the transform
  update; any other trigger is open.
- **Channel 1** (verified gate, meaning open): rectangles fall back to a grey `1 / (1 + d²)` law with no dimmer;
  circles give nothing.
- **Curtains** (verified script and setter): dimmer = 1 − combined opacity. The filter colour is written to `+0xF0`,
  which the window law never reads, so the game ignores the colour cast (inferred for all other readers).
- **Circle windows** (inferred): `+0x210` is never set by their constructor, so their sun patch is likely a small
  square near the centre or none.
