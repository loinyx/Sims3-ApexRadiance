## 1. Capsules from the bones

| File | Content |
|---|---|
| `features/gi_sim_capsules.h` | `Rig` (joints: palette entry and bind place; capsules between joints), `FitRig`, `RigOf`, `GameRigs`; a Sim carries its world capsules (`Sim`), the fixed column stays the fallback (`CapsulesOf`); `Fill` takes any number of capsules a Sim (at most 8) and marks a Sim moved when its capsules change in place |
| `features/gi_pixel_shadows.cpp` | Each Sim draw is fitted when its palette names a rig; the counters line gains `simsFit=` and `simDrawsFit=` |
| `tools/gi_server_test/pixel_check.cpp` | Section 7 (`RigCase`) |

The fit: a joint's place this frame is its bone's palette rows applied to its bind place, so the capsules follow any
pose and any body size. A fit whose capsule lengths differ from the rig's bind lengths by more than 35 % (plus 2 cm) is
refused: a palette in another order breaks the lengths of capsules that span two bones.

What the palette holds, from the skin fill (static, Steam 1.67.2; Ghidra on a copy of the executable):

| Finding | Mark |
|---|---|
| The fill `0x0068F3F0` writes slot i as BindPose[skin][map58[i]] x Pose[map5C[i]], the first three columns transposed (translation in `.w`), 0x30 bytes a slot at drawable `+0x70`; the draw `0x0068FD80` hands `+0x70` and `+0x60` x 3 registers to the shader constant setter (the `SkinMatrices` parameter) | [V] disassembly |
| `+0x58` maps a slot to the skin's joint table, `+0x5C` (built at `0x0068E9C0` from the skin's joint name hash through the rig lookup `0x00575B00`) to the rig's joint | [V] disassembly |
| A palette holds only the joints its mesh uses (`+0x60` slots), in the mesh's own order; the 60-slot cap applies only to the no-pose fallback | [V] disassembly |
| Each slot is a skin matrix (inverse bind x pose), identity at the bind pose | [I] the parameter names; consistent with XR-08's root from the median |
| The skin object (`+0x64`) holds the joint count (`+0x28`), the joint name hashes (`+0x2C`) and the bind poses (`+0x30`) | [V] disassembly |

So a palette's size or order names no age or species: the same body differs by mesh (body, head, hair, shoes). The
Direct3D 9 hook sees only the constants, so **`GameRigs()` is empty and every Sim keeps the fixed column in game**. The
fit is ready for a per-draw rig: a hook on the fill `0x0068F3F0` (callers `0x006905B4`, `0x0070A7D4`) can read each
slot's joint name hash and bind pose and build the rig of that draw (joints named by hash, e.g. pelvis, spine, head,
thighs, calves, feet), which `FitRig` then places. That is the follow-up package.

  six capsules each, ends within 1 cm of the hand-placed joints in model and in world space (0.00 mm measured).

  pixels, multiplier within 2/255 on 99.999 % (one pixel off: worst 22.8/255 at a capsule's silhouette).

## 2. Each object darkened once on the per-pixel path

With `pixelShadows` and `meshCasters`, the server's pass casts the objects' meshes as delta casters and multiplies the
picture, while the Direct3D 9 lamps had already cut the same lamps' light under the objects' blockers (the game's
rectangles and discs in the 3D test). Now the per-pixel path uses MC-4's per-object flag (`Record::meshed`,
`ObjectLegs::MarkMeshed`) with one more source:

| Part | Where | What |
|---|---|---|
| Flag source | `features/mesh_caster_set.h` | `pixelCasts` (set while the pass is open with `meshCasters`); `resolved_`: LITEs the server answered with a mesh of any size; `ServerCasts(id)` |
| Read-back | `features/realtime_gi.cpp` | MC-3's fetch (patch 0022) also runs with `pixelShadows`: its answers tell which LITEs the server resolved. The tiles stay off unless `meshTiles` |
| Gate | `ObjectLegs::Fill` | A record whose object is in the tiles or, with `pixelCasts`, one the server casts gets `meshed`: the GPU's blocker table draws none of its blockers |
| Tiles | `features/rt_outdoor_lamps.cpp` | With `pixelCasts` the tiles take no meshes: the pass darkens them (one path a mesh) |
| On line | `[GiPixel] On: view= testCaster= meshCasters=` | |

Checks [V]: `tools/rt_lamps_test` (680 480 checks, 0 failures): with the pass casting, the record of an object the
server resolved, over the tiles' 2 000 triangles, leaves the 3D test while the missing and unknown ones keep one blocker
each in the drawn table; MC-4's tile checks unchanged.

Limits: [I] the pass takes the 1024 objects nearest the camera and the 16 strongest lamps: a resolved object farther
out, or a lamp outside the 16, loses its box shadow without a mesh shadow; [I] a model over the read-back slot (256 KB)
counts as missing here, so it keeps its blockers and is darkened twice; [O] a kept room's table takes the flag as of
its solve (MC-4's shortcut): a resolution arriving later shows after that room's next solve; [O] the meshes the read-back
keeps (16 MB budget, 1-2 MB a lot measured in MC-3) are kept on the per-pixel path too, though only the answer is used.

## 4. Design: a rig per draw from the skin fill (follow-up, no code yet)

Goal: `GameRigs()` stays empty; instead each Sim draw gets its own `Rig` built from the skin the game just used, so
`FitRig` places capsules for any body, pose and species.

| Step | Design | Mark |
|---|---|---|
| Hook | Rewrite the two CALLs to the fill `0x0068F3F0` (at `0x006905B4` and `0x0070A7D4`) to a `__fastcall(drawable, edx)` wrapper, the call-site pattern of `lot_lighting_motion.cpp`: no prologue relocation. Each site is checked for `E8` to `0x0068F3F0` before the write, else the hook stays off (EA 1.69 gets no rows, as `gcgate.cpp`) | [V] callers; [I] call-site form |
| Read | After the original returns: `n = [drawable+0x60]` (0 < n <= 64), maps `+0x58` and `+0x5C`, skin `= [drawable+0x64]`: joint count `+0x28`, name hashes `+0x2C`, bind poses `+0x30`. All reads in one SEH block; any fault or bound miss = no rig for that draw | [V] offsets; [O] element sizes of the maps and the bind pose layout (3x4 or 4x4, bind or inverse bind) |
| Rig | For slot i: `h = hashes[map58[i]]`; if `h` is one of the named joints (pelvis, spine, head, left and right thigh, calf, foot) it becomes `RigJoint{bone = i, bind = the joint's model-space place}` (the translation of the inverted bind pose if the table holds inverse binds). Capsules from a fixed pair list where both ends are present: thigh-calf and calf-foot per side, pelvis-spine, a head ball: at most 6, under `kMaxPerSim` | [I] |
| Names | Joint hashes compared against a table of the bone names' hashes. Hash and names to confirm offline: read an adult body GEOM's joint hash list with the server's package reader (`meshes_check.cpp`) and match it against FNV-32 of the community bone names (`b__Pelvis__`, `b__L_Thigh__`, ...); no game run needed | [V] disassembly (merge round 5): the rig keys come from `0x00575E80`, per bone `0x00575430(name)` = FNV-1 32-bit (multiply, then xor; not FNV-1a), basis `0x811C9DC5`, prime `0x01000193`, on each char after `tolower`. Check values (FNV-1 32 of the lowercased name): `b__Pelvis__` 0x556B181A, `b__L_Thigh__` 0xC6035E5E, `b__Spine0__` 0x6FA96266 (also in the exe as constants); `b__Head__` 0x0F97B21B, `b__R_Thigh__` 0x83B1355C, `b__L_Calf__` 0x85E195D0, `b__R_Calf__` 0x81B330DE, `b__L_Foot__` 0x23B79422. `0x0068E9C0` hashes nothing: it looks `skin.hashes[map58[i]]` up in the rig's 13-bucket map (`0x00575B00`). [I] GEOM joint hashes use the same function |
| Pairing | The fill writes the palette that the draw `0x0068FD80` uploads unchanged as `SkinMatrices`. The wrapper stores `{n, first slot's 12 floats, rig}` in a small per-frame ring (64 entries); the existing `SetVertexShaderConstantF` hook (register 0) finds the rig by `3 * n == count` and the first 48 bytes. No pointer identity needed | [V] upload chain; [I] content key unique per frame |
| Per Sim | Body, head, hair and shoe meshes are separate draws. Legs and torso come from the draw that holds the pelvis and thighs, the head ball from the one with the head; draws with no named pair add none. Grouping stays XR-08's (root from the median) | [I] |
| Space | [V] disassembly (merge round 5): the palette is model (object) space: the single-bone branch of `0x0068FD80` (`0x00690003`) multiplies the same product by the bound `ObjectToWorldSpaceMatrix`; the multi-bone path leaves ObjectToWorld/Clip unchanged. Check without a game run: whether `0x0068FD80` also sets a world matrix for skinned draws (static). The fit code is the same either way | [O] |
