## How a pass runs

1. Client: `RemixBridge_GiPixelPass(block, size, depth, class, outputs[4])` sends `Bridge_GiPixelPass` with the
   textures' ids and the block as data. No answer is waited for.
2. Server play thread: resolves the ids, `GiPixelPass::run`. It fills a record (block without the boxes, one
   instance a capsule and a box) and calls `ExecuteExternal` with the depth in the read-only depth layout, the class
   texture in the shader-read layout and each output as a copy destination.
3. DXVK's command thread, in stream order: block and instances go into device buffers with `vkCmdUpdateBuffer` (the
   data travels in the command buffer, so a later pass cannot overwrite it before the device has read it), the top
   level is built, the kernel is dispatched between two timestamps, the four own images are copied into the client's
   render targets.
4. A draw the client sends after the pass samples this frame's outputs.

| Point | As built |
|---|---|
| Acceleration structures | Two bottom levels built once, in the first pass: the unit cube (12 opaque triangles) and the unit box. A capsule is an instance of the box scaled to its bounds (custom index 3, mask 2); a static box is an instance of the cube under the client's 3x4 transform (custom index 1, mask 1), so oriented boxes cost nothing. The top level (160 instances at most) is built again every pass, fast-build |
| Capsule lookup | The kernel reads the capsule by the instance's index (capsules come first), where the harness reads it by the primitive index |
| Depth | The INTZ image itself, depth aspect, sampled with `texelFetch` in the read-only depth layout while Direct3D 9 keeps it bound as the depth target. [V] This answers research 16 §3.3's open point |
| Outputs | Own `rgba16f` storage images, copied: a Direct3D 9 render target has no storage usage. All four exist; a null output is not copied |
| Counters | Rays: a running sum the kernel adds to in a mapped buffer. Time: device timestamps around the dispatch, read four passes late without waiting |
| Objects | Created on the first pass and whenever the depth image, the class image or the size changes; freed by `drop()` after a flush and a wait for the device. Nothing else waits |
| Off | No `ID3D9VkExternalPass`: "stock renderer". No ray queries: "no ray queries on this device". Reported once, the pass stays off |

## Formats picked

| Item | Choice |
|---|---|
| Depth | The game's INTZ texture, any depth format with the sampled usage |
| Class input | Optional texture, `r` = class / 3 (XR-05's packing), any size (the kernel scales the coordinate). Absent: every pixel is class 0. The block's flag bit 0 is set by the server |
| Output 0 `raw` | `r` this frame's delta visibility `1 - sum(num) / sum(den)` (1 without a caster), `g` a caster that moved is in reach (XR-09's `num.a`), `b` rays were traced, `a` the guide's device depth. `r` and `g` are XR-05's `sRaw` |
| Output 1 `guide` | `rgb` world normal, `a` linear depth / far (1 where nothing is drawn). XR-05's `sGuide` |
| Output 2 `num`, 3 `den` | XR-09's two sums for the exact form; `num.a` the moved bit, `den.a` the rays of the pixel |
| All outputs | `A16B16G16R16F` render target textures of the client, a quarter of the depth's size. A wrong size or format is a fault |
| Block | 16 lamps, 64 capsules, 32 caster bounds (the client groups them, for example one a Sim; `moved` set by the client with bounds over the old and new place), 96 boxes. The inverse view-projection is the Direct3D row-vector matrix as stored |

## Client exports (patch 0019)

| Export | Returns |
|---|---|
| `RemixBridge_GiPixelOpen(uint32_t* state)` | `S_FALSE` until the server answered (call again a frame later), then `S_OK` with 1 on, 2 off: stock renderer, 3 off: no ray queries, 4 off: other |
| `RemixBridge_GiPixelPass(block, size, depth, class, outputs)` | `S_OK` sent; `E_NOTIMPL` unless the state is on; `D3DERR_INVALIDCALL` for a wrong size or no depth. A pass the server refuses shows as a fault |
| `RemixBridge_GiPixelReadCounters(uint32_t* out, count)` | Words: state, passes, faults, rays low, rays high, rays of a recent pass, dispatch microseconds, output width, height |

No bridge option: the 64-byte block is mapped by the first open, which Apex sends only with its own switch on. The
server logs `[GiPixel] on: ...` or `[GiPixel] off: <reason>` once, and
`[GiPixel] passes=N rays=N raysLast=N gpuUs=N size=WxH faults=N` after 60 passes, every 3600 passes, at the first
fault and before a reset.

## Open issues

- [O] **Reset through the bridge.** In `test_gi_pixel_device` a `Reset` on a DXVK server fails ("device still has alive
  losable resources: 1") and the next read answers device lost. [V] It fails the same way with no pass sent and
  nothing bound, so it is not the pass: creating the textures (INTZ, render targets), `GetSurfaceLevel` and
  `GetRenderTargetData`, then releasing them, is enough. Which call leaves the resource is not found. The test
  therefore replaces the reset by a second set of textures; the reset with the pass is covered without the bridge.
  The game resets through the bridge today, so the cause may be the test's call pattern.
- [O] R-03 notes that patches 0015 and 0016 must be in the series for the game (the test device needs
  `D3DCREATE_MULTITHREADED` without 0016). They are not on this branch; the source tree the patch was built in has them.
- [O] Not run under the Vulkan validation layers.
- [O] The reach test is still a loop over all caster bounds a lamp (XR-09); 32 bounds are the cap.
- [O] A mirrored box transform turns the cube inside out for the culling (marked in the code).
- [I] `forget()` is called for the texture destroy and unlink commands. If the renderer replaces a texture's image
  without a destroy, the pass sees the new handle and rebuilds; a reused handle value without either is not covered.
- [I] The rays counter and the timestamps are read while the device may still be working: they are a pass or more
  behind, never waited for.

## Mesh casters (X-MESHCAST, MC-1 / MC-2)

The instance list of a pass is generic, so meshes slot in without a change to the frame's flow:

- A model command (new, for example `Bridge_GiPixelModel(id, vertices)`) builds one bottom level a model, recorded
  through the same `ExecuteExternal` route. `vkCmdUpdateBuffer` carries 64 KB a call at most: larger meshes need
  chunks or a staging buffer.
- The block gains mesh instances (model id, 3x4 transform, static or delta). `run()` appends them after the boxes
  with custom index 2 and mask 2 for delta casters (the kernel already treats custom index 2 as delta triangles) or
  index 0 / 1 and mask 1 for static ones. Capsules must stay first: the kernel reads a capsule by its instance index.
- `kMaxInstances` and the top level's size grow with the cap; the caster bounds stay the client's.
- With mesh casters the inside-box rule is not needed; the cube's facing flag can stay.

## Handoff: XR-07 (Apex side, not started)

Scope: `features/gi_pixel_shadows.{h,cpp}` on `gi/xr-06`.

1. Option `[patches.RealtimeGI] pixelShadows` (default 0, developer mode) and a view switch. Off: no export is
   looked up, no command is sent, picture byte-equal.
2. On: `GetProcAddress` of the three exports on the bridge's `d3d9.dll`; `RemixBridge_GiPixelOpen` each frame until
   `S_OK`. State not 1: log `[GiPixel] off: <state>` once and stay off (also when an export is missing).
3. Four `A16B16G16R16F` render target textures of a quarter of the depth's size, released before a device reset and
   created again after it.
4. A frame, after the scene and before the compose draw: fill `GiPixelBlock` (camera, inverse view-projection,
   `RealtimeGI::Lamps()` limited to 16 by strength at the camera's lot, capsules and their bounds from the Sim
   proxy, boxes from the object proxy; `samples` 1, `frame` counting up, `bias` and `ambient` as look constants),
   then `RemixBridge_GiPixelPass` with the INTZ texture and the outputs.
5. XR-05's passes on outputs 0 and 1 (`sRaw`, `sGuide` as written; the motion texture from GB-01 or a constant
   while GB-02 is open), then `UpsamplePS` with a multiply blend. `UpsamplePS` wants linear depth: INTZ needs
   linearising there (XR-05 open issue).
6. View: output 0's `r` (and the filtered mask) on screen.
7. Every 10 s in developer mode: `RemixBridge_GiPixelReadCounters`, logged as
   `[GiPixel] passes=N rays=N raysLast=N gpuUs=N size=WxH faults=N`.
8. Runner job `gi-pixel-smoke` (save `ApexTest-Night`, view on): expects `\[GiPixel\] passes=[1-9]\d* rays=[1-9]\d* .* faults=0`,
   fails on `\[GiPixel\] off` and on `faults=[1-9]`. Needs the bridge pair of this branch and the DXVK of
   `native/dxvk` in Bin.

Estimate: 2-3 hours of work, one game run for the smoke job.

Other follow-ups: the reset issue above (30-60 minutes, offline); mesh casters with MC-1 / MC-2.
