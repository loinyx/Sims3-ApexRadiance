## Results and open issues

- Full harness, native D3D9, all sections: 10,078 checks, 0 failures; TerrainHigh ps_3_0 light-invariant 455 of 455.
  The earlier "392 of 455" was not reproduced: 392 is the rule line's "within 3" count (pixels whose target 1 is within
  3 of the albedo colour; the 25 leaf-litter shaders and other blends make the rest), not a light-invariance failure.
  No code change. **verified** (harness, native)
- `run.ps1 -Only` passed its value without `--only`, so every "quick" run through the script ran all sections. Fixed.
- DXVK x32 (`d3d9.dll` built from upstream, x86): all sections but `movers`: 20,130 checks (native + DXVK), 0 failures;
  `movers` with `--mover-limit 300`: 40 checks, 0 failures. **verified** (harness)
- Open: the full `movers` section (7,671 replay shaders) on DXVK x32 stops making progress after a few minutes (no CPU,
  1.5 GB working set, the driver logs `NVVM compilation failed`). **inferred**: the 32-bit test process runs out of
  address space for pipelines; harness only, native passes the full section. Next: link the check with
  `/LARGEADDRESSAWARE` or release the shaders per batch.
- Tidy: `TaaPS` reads 9 more depth / id samples a pixel; measure in game.
