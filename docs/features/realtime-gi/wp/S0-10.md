## Findings

- Cap site `0x006A81DF` = `E8 8C 65 FF FF` -> `0x0069E770`, its only call; room in `ecx` [verified].
- End-of-solve site `0x006A3E65` = `E8 96 CF FF FF` -> `0x006A0E00`, its only call; room in `ecx` [verified].
- Priority returns 0 unless `room+0xF0 == 2`; class > 0 is 0 when above LodChoice. LodChoice `0x0069E710` is
  `[0x01158B00]` only for camera-story rooms (`c == 0`) on a lot with `mgr+0x288 == 1`, else 0 [verified]. The dword's
  run-time value is not in the file [open; must be 2, inferred].
- Cap condition for S1-03: `p > 0` and lot (`[room]+0x90/+0x94`) in the off set and not in the thumbnail set and
  `room+0xF4 > 0` -> return 0 [design, from verified pieces].
- Thumbnail: ThumbnailManager `0x00D59C10`, state 0xB sets the lot lighting manager `+0x4D` through `0x00ADC180(1)`,
  which raises `mgr+0x288` on every story and invalidates every room; state 0x17 polls `0x00AE06B0` until every
  camera-story room shows class 2 and both AO states are 2 [verified].
- No timeout: no clock read in the state machine; the only exit besides readiness is a requester cancel check at the top
  of each tick [verified code; "requester cancel" inferred]. A capped lot waits forever [inferred from verified pieces].
- No LoD switch: the capture installs a model LOD override ("UI/ThumbnailManager/LODOverrideHook", distance 0 per object)
  and a full-detail load request (`renderer+0x2C |= 4`, inferred meaning); no direct call chain reaches the impostor
  path or `0x00ADBAD0` [verified for direct calls; virtual calls not followed].
- Exemption condition: redirect the two `E8` calls of `0x00ADC180` (`0x00AE06EC` with 1, `0x00AE62C7` with 0); lot id
  `[[mgr+0x14]+0x48/+0x4C]` [verified]. `mgr+0x288` cannot be used because the active lot (`+0x4C`, message
  `0x04891B02`) sets it too [verified].
- Impostor: builder state 2 (`0x00AD9E30`) needs a loaded lot, then sync-solves; `0x006A3EC0` solves only rooms in
  state 1/2 with shown class 0, once, at their class (1 or 2) [verified]. The cap does not see this solve. The engine doc
  row that said "while room+0xF0 == 3" is corrected. Whether the impostor albedo bakes room light stays open (inferred
  yes).
