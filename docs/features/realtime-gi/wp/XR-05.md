## Design as built

| Step | Detail |
|---|---|
| Inputs, quarter resolution | Raw: this frame's visibility sample and the bit "a caster moved within reach". Guide: world normal and linear depth. Motion: previous uv minus uv and the class. Previous guide |
| History target | One `A16B16G16R16F`: fast sum and count, settle sum and count. Sums, not means, so 16 samples of 0 or 1 stay exact |
| Settle accumulator | Same pixel only, no reprojection. Adds a sample only while the camera is still, no moved caster is in reach and the class is not 3. Dropped on a reset, a moved caster in reach, a depth or normal change. Stops at 16: the fixed set is complete and the pixel never changes again, with the passes still running |
| Fast accumulator | Reprojected with the motion vector, 4 taps, each tap rejected on depth (tolerance grows with the slope of the surface), on normal (cosine under 0.9) and off screen. Running mean capped at 16, at 4 near a moved caster. Class 3, no valid tap or a reset: this frame's sample with count 1 |
| Variance clip | Fast mean clipped to mean ± 1.5 sigma of the raw 3x3, near a moved caster and while the count is under 9 afterwards. Off while the camera pans |
| Shown value | Fast mean cross-faded into the settle mean by settle count / 16, so settling has no pop; at 16 the settle mean alone |
| Spatial filter | 5x5 a-trous at steps 1, 2 and 4, weights from depth, normal (power 32) and the tap's count. Step 4 only by `(1 - count / 16)` and only where the value after the narrow passes is neither fully lit nor fully dark |
| Fallback | A rejected pixel is its one sample with count 1 through all three passes: never the raw sample |
| Upsample | Full resolution, 4 taps, bilinear weight divided by the depth difference to the full-resolution depth; the tolerance uses the tap's normal, so a sloped floor does not turn into blocks |

Differences from research 16 §4:

- Two accumulators instead of one. With one, the exact 16-sample mean and a history that follows motion exclude
  each other: samples taken during motion stay in the mean, and a frozen picture keeps them for good.
- Freeze is per pixel, not per picture. A still part of the picture is byte-equal while a Sim walks elsewhere.
- The clip is not applied to a still pixel or during a pan: on raw values of 0 or 1 it pulls a light penumbra to
  fully lit whenever its 9 neighbours happen to be lit.
- The kernel is not scaled by the hit distance; the count and the value decide the width. See open issues.

## Results

640 x 360 picture, 160 x 90 mask, one lamp ball, a static caster and a class 3 caster that the static one shadows.
100 frames a sequence: 20 still, 40 moving, 40 still. Values in 1/255 of full visibility, static pixels, columns over
the moving frames (still camera: over frames 2-16).

| Sequence | Variant | Change a frame | Error to reference | Worst frame within 4/255 | Trail |
|---|---|---|---|---|---|
| Still | Raw sample | 0.262 | 0.67 | 98.4 % | - |
| Still | Spatial only | 0.045 | 0.32 | 98.6 % | - |
| Still | Spatial + history | 0.024, then 0 | 0.15, then 0 | 98.8 % | - |
| Pan 0.4 degrees a frame | Spatial only | 0.124 | 0.36 | 98.4 % | - |
| Pan | Spatial + history | 0.117 | 0.07 | 99.4 % | 0 |
| Pan | Same + clip while panning | 0.114 | 0.06 | 99.0 % | 0 |
| Sim walks 0.06 m a frame | Spatial only | 0.152 | 0.47 | 97.3 % | 1 |
| Walk | Spatial + history, no clip | 0.092 | 0.48 | 98.1 % | 8 frames |
| Walk | Spatial + history | 0.093 | 0.45 | 98.1 % | 1 frame |

Reference: the exact 16-sample mean of each mask pixel through the same spatial passes and upsample. Trail: frames
in a row in which a static pixel out of the moved caster's reach is 8/255 or more darker than a fully lit reference.

- [V] Still: frames 17-100 are byte-equal with the passes running each frame, and equal the reference on every
  pixel (maximum error 0). Convergence takes 16 frames; spatial only never settles (last change in the last frame).
- [V] A class 3 pixel has no history. If the tracer cycles its sample set the picture never settles (maximum change
  117/255 on the shadowed Sim); with one fixed point of the set it is byte-equal. **The tracer must trace a fixed
  point on class 3 pixels.**
- [V] Pan: 99.4 % of static pixels within 4/255 in the worst frame (XR-05 target 99 %). 16 frames after the stop the
  picture equals the reference and is byte-equal from then on, in both moving sequences.
- [V] Moving caster: with the clip no static pixel keeps a shadow more than 1 frame after the caster left its reach
  (target 4); without the clip 8 frames.
- [V] The value gate of the wide pass removed a 10-frame halo behind the moving shadow: before it, pixels that had
  just left the reach had a low count and pulled the shadow in through the step-4 kernel.
- [V] Shaders compile to `ps_3_0`: 2712, 1924, 1456 and 1152 bytes; a mask pixel costs 13 fetches in the temporal
  pass (9 more when the clip is on) and 52 a filter pass; an upsampled pixel costs 9.
- [I] Inside the reach of a walking caster the history does not lower the mean error (0.45 against 0.47 spatial
  only), it lowers the change between frames (0.093 against 0.152): the shadow is steadier, not more exact.

## Compute equivalent

For route D (research 16 §3) the same three kernels run as compute shaders after the trace, on the tracer's device:

| `ps_3_0` | Compute |
|---|---|
| `TemporalPS`, render target `A16B16G16R16F` | `imageStore` to an `rgba16f` image; the fast taps become 4 `texelFetch`. Can be merged into the trace kernel: it already holds the sample, the reach bit and the guide of the pixel |
| `AtrousFirstPS`, `AtrousPS` | Three dispatches with `texelFetch` at integer offsets, or one dispatch a step with a shared-memory tile for steps 1 and 2 |
| `UpsamplePS` | Stays in the Direct3D 9 compose effect: it must read the full-resolution depth and multiply the back buffer |
| Constants `c0-c4` | One uniform block |

A pixel whose settle count is 16 and whose reach bit is clear needs no ray: the trace kernel reads the history image
first and skips it. The reach test still runs for it each frame (bounds only).

## Interface to XR-04 and XR-06

- XR-04 writes per-lamp counts `u` and `d`. This filter takes one value a pixel and frame. First version [I]: the
  one-sample multiplier term `1 - m` of the frame. The mean of ratios differs from the ratio of the 16-frame counts
  where a static occluder cuts the lamp partly; the exact form accumulates numerator and denominator as two sums
  (the settle pair doubles, a second target).
- XR-04's reach test gives "a caster is in reach"; the filter needs "a caster that **moved** this frame is in reach,
  at its old or new place".
- A lamp that changes or a camera cut sets the reset constant.
- Double darkening under the chair (XR-04 open issue): the filter is linear in the mask and neither adds to nor
  hides it. It belongs to the compose rule (XR-07 or XR-10).

## Open issues

- [O] The scene is the harness's own (planes and balls), not XR-04's lot: `gi/xr-04` landed while this was built.
- [O] One lamp. Four lamps need four values a pixel or the multiplier form above.
- [O] Penumbra-scaled kernel radius (research 16 §4) not built: no hit distance in the inputs.
- [O] Rejection compares the current depth with the stored depth, not with the reprojected depth. Fine for a pan;
  a fast dolly rejects more than needed and falls back to the spatial filter.
- [O] The harness takes linear depth and a packed motion and class texture. In the game: INTZ needs linearising in
  `UpsamplePS`, motion is GB-01's `G16R16F`, the class comes from GB-02.
- [O] Shimmer was measured as numbers only; no picture pair was looked at. Foliage (class 3 with wind) is a fixed
  noise pattern through the spatial filter: stable, but its look is unjudged.
- [O] No timing.
