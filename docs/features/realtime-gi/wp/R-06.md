## What the patch adds to 0018

| Piece | What it does |
|---|---|
| `RemixBridge_GiQueryPoints(points, count, scales, lamps, sceneTicket, &ticket)` | Up to 256 points (position, normal) and an rgb weight a lamp (missing lamps weigh 1), sent inline in `Bridge_GiQuery`. One query in flight; `D3DERR_WASSTILLDRAWING` otherwise |
| `RemixBridge_GiReadPoints(ticket, out, count)` | Polls as `GiPoll`; on `S_OK` copies four floats a point from the block's query answer |
| Query kernel (`gi_solve.comp` pass 3) | One workgroup a point: each settled lamp's direct light by the same shadow rays as pass 1, plus the scene's ray count of cosine rays gathering the hit texels' settled sum layers, weighted. Lamps not yet settled count nothing (the answer says how many were used). Lamps whose box does not hold the point count nothing |
| Touch box | Every solve with settled bounces writes the box and count of texels whose sum layer is over 0.5/255 (wp/X-REBAKE.md) into `GiTouchEntry[256]` of the block, seqlock-guarded. `RemixBridge_GiReadTouch(lamp, box, &texels)` reads it; `S_FALSE` before the first settled solve |
| Region-scoped dispatch | A lamp with a box solves only the texels in it: the worker builds the index list on the CPU and the direct and gather passes run over it (binding 10). `server.giListDispatch = False` visits every texel and skips the ones outside, for comparison; both give byte-equal layers |
| Refusals | Scene blobs with a non-finite triangle, patch or texel value, lamp blobs with a non-finite position, colour or NaN box, and query points with a non-finite value or a zero normal poll `D3DERR_INVALIDCALL` |
| Block | `kLayoutVersion` 3: query answer at 919680, touch entries at 923792, about 915 KB in all |

## Checks [V]

Synthetic scene of `check.cpp` (9120 texels, 3 lamps), both levels:

- Point queries against a CPU reference of the same kernel (same rays, the offline layers): 256 of 256 points within
  1/255, worst 0.19/255 (rays) and 0.08/255 (compute).
- At 192 texel points against the bridge's own sum layers: mean 4.27/255, bias -0.44/255. A query gathers along its own
  rays, not the texel's links, so it differs by the noise of one 256-ray gather; the test bounds the bias (1/255) and
  the mean (8/255). Byte-equal values at texels would need the query to reuse the texel's links, which only exist at
  texels; the rig write queries points in the air.
- A lamp at half weight answers exactly half. Refusals as listed above.
- Touch boxes equal the box and count computed from the read-back layer for every lamp (4480, 2304, 4477 texels).
- Query GPU time: 50 us (rays), 3.3 ms (compute) for 256 points and 3 lamps.

Lots of `rebake_check.cpp` (60, 120, 200 lamps; each lamp scoped to its room grown by one room on its story):

| Lot | Layer GPU median, list | Layer GPU median, every texel | All layers, list | Touch box median (unscoped offline) |
|---|---|---|---|---|
| 60 lamps, 3124 texels | 1.2-1.3 ms | 1.2 ms | 83-87 ms | 331 (396) |
| 120 lamps, 6260 texels | 2.1-2.4 ms | 1.3-3.7 ms | 251-323 ms | 374 (417) |
| 200 lamps, 10420 texels | 2.1-2.2 ms | 5.1-8.4 ms | 458-490 ms | 379 (426) |

- The list-scoped layer cost stops growing with the lot (about 2 ms from 120 to 200 lamps); visiting every texel grows
  with it. Both dispatches give the same layer hashes.
- No scoped lamp lights a texel outside its box. Inside the boxes 99.88-99.94 % of texel values are within 1/255 of
  the unscoped offline solve.
- [V] The room-plus-one-room box clips light: the unscoped layers put 8-11 % of their lit texels (over 0.5/255)
  outside it (1876 of 24363, 5640 of 52240, 9933 of 90465). A lamp's light reaches past the next room through doors in
  line. The touch box medians drop by 10-16 % accordingly.

## Open issues

- [O] Box size: room plus one room drops 8-11 % of lit texels. S2-01 decides between a larger box (two rooms, or the
  touch box of the unscoped first solve grown by a margin) and accepting the clip.
- [O] The batched gather sizes its submission from the full-texel slice units, so a list-scoped layer's longest slice
  ran up to 6-10 ms, over the 2 ms budget (`server.giSliceUs`). Fine for the self-test; R-G1 should size scoped batches
  from the list length.
- [O] The 200-lamp lot's layer timings vary 1.5-2x between runs; the machine was not quiet (clean timing is R-G1).
- [I] A query costs one dispatch for 256 points; the rig write needs one point a model, so one query a frame covers it.
- Not tested with the DXVK server renderer (`DXVK_X64` was not set in this run).
