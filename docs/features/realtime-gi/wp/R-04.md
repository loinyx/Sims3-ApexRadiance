## What the patch adds to R-03's

| Piece | What it does |
|---|---|
| `RemixBridge_GiSubmit(data, size, kind, &ticket)` | Copies a part into one of two shared submit slots of 448 KB and sends `Bridge_GiSubmit`. A blob over a slot goes in parts: every part but the last carries `GiSubmitMore` (0x100) and gets no ticket. `D3DERR_WASSTILLDRAWING` while both slots wait for the server (it frees them at its next command). Kinds: 1 scene, 2 lamp table |
| Scene blob (`util/util_gi.h`) | `GiSceneHeader` (counts, rays a texel, shadow rays, fixed gather count), `GiSceneTriangle` (three points, front and back patch), `GiScenePatch`, the patch map, `GiSceneTexel` (point, normal, reflectance, target pixel) |
| Lamp blob | `GiLamp[]`: point, ball radius, colour, region box. Lamp i is layer i. Light = colour x cos / d^2 x the visible share of the ball; the caller folds the game's law into the colour |
| Per-triangle texel index | A hit names its texel through the hit triangle's patch for the side the ray came from: a planar grid (origin, two scaled axes, size) into a map of texel indices. No story height, no tile lines, so split levels and diagonal walls need nothing more. A side without a patch (furniture, outdoor faces) blocks light and returns none |
| Kernel `server/gi_solve.comp` | R-02's `solve.comp` with the patch index and slice offsets; five SPIR-V builds (links and direct with ray queries and without, the gather). `server.giMaxLevel = 1` keeps a ray-query GPU on the compute level |
| Worker | Scene submit: checks every count and index, uploads, builds the ray structure (rays) or a 1 m grid (compute), traces the links in slices. Solve: the lamp's direct pass, then the fixed count of gathers, read back and written by each texel's pixel as half float or 8-bit. Layers stay on the device, and a lamp whose 56 bytes did not change is not solved again |
| Slices | Each submission is timed with GPU timestamps and the next one is sized to `server.giSliceUs` (default 2000, the X-REBAKE budget). Links slice by texel columns and ray runs; whole gathers that fit the budget go several a submission. `server.giSliceIdleUs` (0) waits between slices |
| Solve call | `RemixBridge_GiSolve(texture, layer, sceneTicket, &ticket)`: `layer` = lamp index, plus `GiLayerWhat` from bit 16 (0 indirect, 1 direct, 2 sum). A scene ticket that is not the worker's scene answers `D3DERR_INVALIDCALL`. Scene ticket 0 keeps R-03's pattern pass |
| Uploads | A result over what is left of the 1 MB budget goes in bands of rows over several passes (R-03's 2 MB single copy is gone). At most eight staging textures are kept |

## Shared block, layout version 2

`"Gi"` mapping, 919 680 bytes (about 900 KB of the client's address space once opened). All fields 32-bit.

| Offset | Field |
|---|---|
| 0 | `magic` "GI01", `layoutVersion` 2 |
| 8 | Counter words 0-13, read by `RemixBridge_GiReadCounters` from here: `level`, `capBits`, `heartbeat`, `workerHeartbeat`, `lastError`, `jobsQueued`, `jobsDone`, `gpuUsLast`, `uploadUsLast`, `uploadUsMax`, `uploadBytesMax`, `behaviorFlags`, `sliceUsMax` (12), `slicesLast` (13) |
| 64 | Counter words 14-21, `objectCounters[8]`: **kept for the object export** (objects, models resolved, models missing, index ready, four spare). Nothing writes them yet |
| 96 | 64 answer slots of 32 bytes (`answeredSeq`, `hresult`, `kind`, `size`, `gpuUs`, `uploadUs`) |
| 2144 | 2 submit slots: `consumedSeq`, 12 bytes kept, 448 KB of data |
| end | R-06 appends the point-query slot (version 3) |

`kCounterWords` is 22. A later export appends its slots after the submit slots and raises the version.

## Scheduler spec of wp/X-REBAKE.md: what is where

| Rule | State |
|---|---|
| GPU slice of about 2 ms a submission, both levels | Built: `server.giSliceUs = 2000`, measured a slice |
| Fixed 16 gathers | Built: the scene header's count; the test uses 16 |
| Batched gathers a submission | Built for one lamp. Several lamps a dispatch is not built |
| Region scope | Built as a box a lamp (`GiLamp.boxMin/boxMax`, empty = whole scene): texels outside get no light and return at once. The dispatch still visits every texel, so the list-scoped dispatch of the spec is open |
| Touch box written by the solve | Not built: the server holds the layer and the texel points, so it can return the box with the answer (the answer slot has no room; it goes with R-06's slot) |
| Whole-layer swap with crossfade | Client (S2-01): solve into a second texture and fade. Note: a target over the 1 MB budget arrives in bands, so only a layer of at most 1 MB swaps whole in one pass |
| Moved lamp after 2 still frames, build edits after 0.5 s idle, queue cap 64, priority by view and distance | Client (R-05): the server solves tickets in the order sent and `RemixBridge_GiCancel` stops one between slices |
| Toggle, dim, recolour without a solve | Client compose. A colour change in the lamp table does solve again here, so the client keeps the table's colour fixed (unit) and scales in the compose |

## Deviations and limits

- Reflectance is part of the scene's texels. A reflectance-only change is a scene submit, which traces the links
  again; a kind that replaces only the reflectance is not built.
- The scene and lamp blobs are trusted for their floats only: counts, patch ids, map entries and sizes are checked,
  NaN positions are not.
- The compute level refuses a scene wider than 2 000 m in x or z (its grid).
- Device reset drops open submits as well as solves (`D3DERR_DEVICELOST`); the scene the worker has built stays.
- The offline tool keeps its own `solve.comp` (world-cell map) as the independent check of the patch index; the two
  kernels are otherwise the same source by hand.
- Patch 0016 (reference count fix) must be in the build before in-game use (wp/R-03.md).
