## What it records

Each call to the device's `SetPixelShaderConstantF` / `SetVertexShaderConstantF` that reaches Apex's detours, as the
caller asked it (before any Apex callback; nothing is changed), keyed by the caller's return address:

- Owner of a new calling site, classed once: the game's exe, Apex's own module, or any other module.
- Per kind and owner: the registers written (a difference array, printed as runs such as `c0-c7, c10-c24`), the highest
  over the session, in the last frame and in the worst frame.
- Per site (256 kept; more are counted as dropped): calls, lowest and highest register, writes into the reserved
  frame-block registers, calls past the last register (`c223` PS, `c255` VS).
- Reserved: pixel `c208`-`c223` and vertex `c242`-`c251` (research 13 §2.4, §2.5; vertex was `c228`-`c251` until the
  first run). A write there by Apex is not counted;
  by the game or another module it is, and that site is logged once as a warning.

Cost: two relaxed counters, two maxima and one hash probe a call; module lookup only for a new site. Developer mode
only (`kDevToolsBuild && !kPublicBuild`), compiled out of the players' build.

## Output

- Log, `[ConstRange] Reserved register written: <kind> <range> by <module>+0x<offset> (<owner>), N of its M calls`
  (warning, once a site).
- Log, `[ConstRange] PS: highest written game cN Apex cN other none, reserved c208-c223 written by others 0 times; VS: ...;
  K calling sites, F frames`, after a new site or a new highest register, at most every 600 frames.
- Frame profiler report (`ApexRadiance_Hitches.txt`): "Shader constant registers written", the summary line, one
  line per kind and owner, one row per site. Game sites read directly as addresses, for example `TS3W.exe+0x39E10A`
  is `0x79E10A` (image base `0x400000`).

## Smoke job (`const-range-smoke`, for S0-G2)

`tools/ingame_runner/jobs/const-range-smoke.json`, Apex + bridge (Bin state `apex`), developer build of this branch,
about 8 minutes: night save, developer mode, frame profiler started at load with a report every 60 s; a pan over 8 lots
at 40 m (3 passes of 40 s), 2.5 min of live mode, 60 s in Create a Sim (the household's Sim palettes), back to live,
2 min.

- Fail: any `[ConstRange] Reserved register written` line (game or another module wrote pixel `c208`-`c223` or vertex
  `c242`-`c251`); a crash.
- Expect: the `[ConstRange] PS: highest written game c..` summary line.
- Read in the results: the last summary line, and the report's per-site rows. Expected from research 13 and the S0-04
  census: game PS writes at most about `c24` (`0x79E10A` / `0x79E167`), game VS writes at most `c241` (pet and ghost
  fur, research 13 §2.5; `c227` without them)
  (`0x79E0F6`-area / `0x79E150`-area and InstancingEmulation `0x696A7B` / `0x696A97`). A game write between
  `c25` and `c207` (PS) does not fail the block but is reported, since the parameter tables may name registers a shader
  never reads [inferred, research 13 §2.2].
- Not part of the job: research 13 §3's `perfLogIntervalFrames` bridge counts. Its batching verdict is already
  settled from source (V-src), and changing the bridge's config would need a Bin-side edit outside the runner.

## Findings

- [verified, build] The histogram compiles into the developer flavour and out of the public flavour.
- [verified, offline] Runs, maxima, reserved and out-of-range counts and the once-per-site log behave as specified on
  synthetic calls shaped like the game's two writers.
- [inferred] Calls Apex makes through `CallOriginal*` (none for shader constants today) and writes a module makes
  below Apex's detour are not seen. A mod that wraps the device in front of the bridge would appear as "other" with
  its forwarding site, hiding which game site it forwards.
- [open] Whether horse and pet palettes (SimHorse reads up to VS `c227`) draw in the night save; the job's CAS visit
  covers the household's Sims only. If the save has no horse, a horse-world run is the follow-up.

- [verified, run] First run (ApexTest-Town): the game wrote VS `c228`-`c229` from `0x79E152` (16 calls), the vertex
  tables' pet fur records. The reserved vertex range moved to `c242`-`c251` (research 13 §2.5).
