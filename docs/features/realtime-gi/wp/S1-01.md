# S1-01: module skeleton

**Status:** done. Branch `gi/s1-01`, commit "realtime-gi: module skeleton, switches and start line".

Deliverable: [features/realtime_gi.h](../../../../features/realtime_gi.h), [features/realtime_gi.cpp](../../../../features/realtime_gi.cpp)
(module and the feature `RealtimeGI` with its registration), one `ClCompile` line in `ApexRadiance.vcxproj`.

## What it does

- **Switches.** `[patches.RealtimeGI]`, `enabled` false by default (`enabledByDefault = false`, `experimental = true`).
  Registered keys, saved as names: `backend` (`auto`), `lots` (`active`), `solveCap` (`off`), `bufferScale` (`1`),
  `indirect` (`off`). The other keys of design.md section 5 are added by the packages that use them. The feature is in
  no menu list (`apex_gui.cpp` draws named lists only), so it is reached through the TOML file alone.
- **Off:** `Install` never runs, so no hook is registered and no resource is created. Verified by reading the code
  path: the only side effect of the module is `RealtimeGI::Start`, called from `Install`.
- **On:** `Start` selects the back end, registers one Present callback named `RealtimeGI` and prints the start line
  `[RealtimeGI] On: lots=0 cap=<mode> scale=<n> indirect=<mode> backend=<name>` (design.md section 6). `lots=0`
  until S1-02 adds the lamp snapshot of a GI lot. A requested back end that is not available logs one fallback line.
- **Profiler line:** the D3D9 hook registry times the Present chain by name while the frame profiler is on, so the
  module's ms a frame shows as "RealtimeGI (Present)". Draws and other device calls by GI code are counters
  (`Counter::Draws`, `Counter::DeviceCalls`) for the packages that issue them.
- **Counters:** in developer mode, every 10 s, one line with frames, back end, draws, device calls and the four
  must-be-0 counters (class 1-2 solves on GI lots, synchronous `GetRenderTargetData` from GI code, locks of GI
  resources, `debugRedrawAll` differences). A non-zero must-be-0 counter writes the line as a warning.
  `RealtimeGI::Add(Counter, n)` is the entry point for later packages.
- **Back end selection stub:** `SelectBackend(requested, serverExport, rayQuery)`: no GI export on the bridge gives
  `d3d9`; with the export, `auto` and `serverRays` take `serverRays` when ray queries exist, else `serverCompute`.
  Checked by `static_assert`s in the header (every request with and without export and ray queries). The export and
  ray query probes return false for now (`shortcut:` comment in the code): no bridge exports the GI interface yet.

## Findings

- Verified: `ApexPatch` features reach the menu only through the named lists in `apex_gui.cpp`, so a registered
  feature without a list entry is TOML-only (developer-mode only as design.md section 5 asks until S6).
- Verified: the Present chain is timed by callback name while the profiler is on (`framework/d3d9_hooks.cpp`,
  `features/frame_profiler.h` `PresentHookTimingActive`); no profiler change is needed for the module's line.
- From S0-05 (branch `gi/s0-05`), carried forward for S3-02: the lamp block of the object copies is a looped
  index-cell block (`rep` loop, one index texel a lamp), 110 `ps_3_0` slots for any lamp count; constants cannot be
  indexed in a loop, so the unrolled constant form is not built. Nothing in S1-01 depends on it.
