## What it does

**Scene blob (`GiScene::Build`).** From the lot proxy (`RtLampProxy::Lot`), in world space (the lot's matrix inverted):

| Part | How |
|---|---|
| Triangles | `RtLampProxy::Build(lot, open tops)` plus a floor for every tile with one where the proxy has none (ground story, stories whose placed floors were not read), plus object shapes |
| Texels | `density` a metre (2 in game, 4 in the test) on the room side of each surface: floors and ceilings of roofed quadrants, wall faces toward a roofed quadrant (a quarter metre off the edge's middle). Openings, outdoor faces, slab sides and shapes have no texels |
| Patches | One a story for floors, one a story for ceilings (planar grids over the story's tiles), **one a wall line and side over all stories** (R-04's rule). Lines are keyed by direction and offset, so diagonal walls get their own patch |
| Triangle to patch | Walls by their line and the side the winding faces; ceilings (down: that story's ceilings; up: the floors of the story above where a placed floor lies on that ceiling); added floors (up: floors; down: the ceilings below); slab tops (up: floors) |
| Reflectance | Floors: the quadrant's floor colour (tile section `+0x80`, S0-12), linearised, times 0.6 (white = bare tile = 0.6) [I: scale until S6-01]. Walls 0.7, ceilings 0.8 (no colour in the lighting data, S0-12) |
| Pixels | Kept per texel (keyed by its lot-space place and facing) across rebuilds of a lot; new texels take freed pixels first. The atlas (256 wide) has 25 % headroom; only when it grows do all layers re-bake |

**Edit box.** A rebuild diffs against the last build: texels added, removed or with another reflectance, triangles added
or removed. The union of their tiles (and stories) is the edit. The scheduler's `Backend::SubmitScene(edit, whole)` now
takes the box by reference: the bridge back end narrows the scheduler's whole-lot edit to it. An unchanged scene is not
sent and re-bakes nothing (lamp-free game edits that bumped `LotGeometryKey`, S2-01 finding, now cost nothing). A
reflectance-only change is a full scene submit (R-04 has no reflectance-only kind) but re-bakes only the lamps whose
box holds the repainted tiles.

**Edit sources in game.** Every 10 frames the generation of the GPU room lamps' kept occluders
(`RtOutdoorLamps::KeptLot`, rebuilt by that path only when the lot really changed), every 30 frames a hash of the floor
colours (a repaint does not change the proxy). The scene itself is built from `KeptLot` too, on the render thread
(`ExportLotProxy` runs only on the light tree thread).

**Compose (`GiCompose::Composer`).** Two DEFAULT-pool `A16B16G16R16F` slots a layer (atlas size), the irradiance atlas
the same size. Each frame after the scheduler's Tick: fades that ended show their new slot; the composed tiles' pixels
(`Built::tiles`) are drawn as points: first set to 0, then per lamp `colour x lerp(shown, incoming, blend)` added (blend
ONE, ONE), one draw a lamp. Colour is the snapshot's (`base x dimmer x fade`, 0 when off); the layer is unit colour. Draws
go past Apex's hooks (`CallOriginalSetTexture`, `CallOriginalDrawPrimitive`), the state is kept in a state block.
`Counter::Draws` counts them.

**Scheduler.** A lamp whose layer is fading is not issued until the fade ends (with two slots a layer, both are shown
then). `Box::Union` is inline (the builder uses it outside the scheduler).

**Solve request.** The lamp table now sends the ball radius of Shadow softness (`Penumbra::Radius()`) instead of 0.1 m,
and a region box when one is safe:

| Case | Region box | Touch box to the scheduler |
|---|---|---|
| First solve of a lamp, lamp moved, or any scene change since its touch box was read | none (whole scene) | the server's (patch 0021), as the texels' tiles and stories; without 0021 the lamp's reach (range, 1 to 6 m) |
| Same scene and place as its last touch box (a softness change) | that touch box grown by 0.5 m | the server's |

A room box clips light that goes through doors (R-06: room plus one room drops 8-11 % of the lit texels), and an edit
can open a way out of an old touch box, so after an edit the solve is unscoped and reads a new touch box.

**Back end selection.** `ServerRayQuery()` is false until `GiOpen` answers with the rays level. Start takes
`serverCompute` for `auto` before that; when the answer comes the back end is chosen again (`[RealtimeGI] Back end ...`
line; level none switches the scheduler off). The start line prints the back end in use at that time.

## Findings

- [V] The server seeds a texel's rays by its index in the blob (`Pcg(i * rays + r)`), so a check against an offline solve
  by texel needs the same texel order: the offline test now solves in the builder's order. With another order the layers
  differ by up to 57/255 a texel (30 % over 1/255) while room means agree.
- [V] Executables whose name contains "patch" ask Windows for elevation (installer detection): keep test tool names clear
  of it.
- [I] `KeptLot` is the GPU room lamps' active lot; like `OutdoorDelta::LotLamps` (S2-01) it exists only while that path
  runs, so with it off the scene is never built and nothing is issued (the scheduler waits on the scene).
- [I] The lamp's story (`+0xD0`) is taken as the proxy's story index for tile keys; on a foundation house the proxy's
  level 0 is the terrain story (room-light-maps.md). A mismatch would compose a lamp's layer on the wrong story's tiles.
  Check in game (R-G1).

## Open issues

- **The consumer:** no shader reads the irradiance atlas yet (S1 has no direct or `roomAmbient` consumer in the code;
  `RealtimeGI` draws nothing into the game's maps). The next package binds it: the game's light maps sample it through
  the scene's patches (a texel's place gives its pixel), or a pass writes it into Apex's copies of the room maps.
- Device reset: the slots, the irradiance atlas and the vertex buffer are DEFAULT pool and are not released on a reset
  (the bridge answers open tickets `D3DERR_DEVICELOST`, R-04) [O].
- Memory: two full-atlas slots a layer (at 2 texels a metre a 30 x 30 two-story lot is about 25 k texels, 400 KB a
  layer) [O: per-layer sub-atlases from the touch box].
- The compose colour has no calibration against the game's law or the look constants (S6-01).
- Scoped solves are rare under this rule (an edit or a move solves unscoped). If unscoped re-bakes after edits are too
  slow in game (R-06: 5-8 ms a layer visiting every texel on a 10 k-texel lot), scope them to the old touch box grown
  by the lamp's reach and solve unscoped when the new touch box reaches the scope's edge [O, R-G1 timing].
- Scoped slices run 6-10 ms until R-G1 sizes scoped batches from the list length (R-06).
- In game: `gi-sched-smoke` runs on the fake back end; a server-back-end smoke (scene sent, layers landed, compose draws,
  `overBudget` 0) is R-G1's.
