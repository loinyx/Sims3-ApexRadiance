## What the patch does

- Client exports `RemixBridge_GiOpen`, `RemixBridge_GiSolve`, `RemixBridge_GiPoll`, `RemixBridge_GiCancel`,
  `RemixBridge_GiReadCounters` (`client/d3d9_gi.cpp`). Commands `Bridge_GiOpen`, `Bridge_GiSolve`,
  `Bridge_GiCancel`, all with `FlagBits::AsyncResult`.
- Shared block `"Gi"` (`util/util_gi.h`), 2112 bytes: header with level, capabilities, heartbeats, counters and the
  server device's `BehaviorFlags`, then 64 answer slots of 32 bytes (hresult, kind, size, worker and upload
  microseconds). Layout version 1; R-04 appends the submit slots and the point-query slot.
- Worker (`server/gi_worker.cpp`): own `VkInstance` and `VkDevice` through volk, on the GPU whose `deviceUUID` equals
  DXVK's (read through `ID3D9VkInteropDevice::GetVulkanHandles`), else the first discrete GPU. A compute-only queue
  family when there is one. Ray query, acceleration structures and buffer device addresses are enabled when present
  (level 2), else compute only (level 1). One pass (`server/gi_pattern.comp`) writes a ticket and layer pattern into a
  host-visible buffer.
- Play thread (`server/gi_server.h`): checks the target (DEFAULT pool, `A16B16G16R16F` or `A8R8G8B8`), queues the job,
  and at `Present` and every 64 commands (0017's poll points) copies finished jobs through a cached SYSTEMMEM staging
  texture and `UpdateSurface`, within `server.giUploadBudgetKB` (1024) a pass. A later solve for the same target and
  layer supersedes an unapplied one. Reset, ResetEx and device destroy answer open tickets `D3DERR_DEVICELOST`.
  The target is looked up again before every copy, so a destroyed or unlinked id gets an error, never a stale write.
- Options: `client.giServer` (default off), `server.giServer` (default on; off simulates a server without GI support),
  `server.giUploadBudgetKB`.

## Deviations from server-export.md

- `RemixBridge_GiOpen` never waits. It returns `S_FALSE` until the server answers and the worker is ready, and reports
  none after 2 s without an answer. A blocking 100 ms wait failed once in the self-test: the open command can reach the
  server only with a later Present.
- `RemixBridge_GiSubmit` and `RemixBridge_GiQueryPoints` are not in this patch (R-04, R-06); `sceneTicket` is carried
  but unused. `RemixBridge_GiReadCounters` is added for R-05's counters.
- A cancelled ticket is never answered; an unknown ticket in `RemixBridge_GiCancel` returns `D3DERR_INVALIDCALL`, as in 0017.
- `RemixBridge_GiSolve` casts the texture with `bridge_cast` like 0017, so a texture that is not the bridge's is not
  detected in release builds.

## Build and patch order

- Patch 0018 applies after 0001-0014 and 0017, with or without 0015-0016 (both orders checked with `git apply`). The
  new commands sit after `Bridge_UnlinkVolumeResource`, so later command numbers shift; client and server are always
  one build.
- `build.cmd` now also fetches Vulkan-Headers and volk (tag `vulkan-sdk-1.4.350.1`) and the glslang 16.6.0 release into
  `src\submodules\`, the versions R-02's `tools/gi_server_test/run.ps1` pins. No Vulkan SDK install is needed. An
  existing `src\` needs deleting once to fetch them.
- Built: x86 client `d3d9.dll`, x64 server `NvRemixBridge.exe`. Not packaged, no game run.
