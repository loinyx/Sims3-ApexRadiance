## What it does

- **Snapshot.** Render thread, in the module's Present callback, only in a world (`WorldSession::InWorld`): every light
  the game enumerates (`0x006ACF70`, the same visitor and Steam byte check as `LotLightBridge`; indoor lamps are in no
  light cell, research 01 section 3) is read into `RealtimeGI::Lamps()`. Fields per research 01 section 2: type, lot,
  room, story, flags, head position, base colour, dimmer, fade, range, the raw spot and shaded-lamp cones, and Apex's GPU
  law of the lamp (`RtOutdoorLamps::OwnLotLaw`, lot lamps of classes 3-6, 9-11). Colour = base x dimmer x fade while on.
  The light pointer is an identity only; nothing is read through it in a later frame.
- **On state.** On = alive, enabled, lit (`(flags & 0x61) == 0x61`), dimmer and fade over 0. A new on state is taken only
  when two reads agree (`DebounceOn`, `static_assert`-checked): the light tree thread rewrites the lit bit under the
  reader. A lamp waiting for its second read is read again the next frame.
- **When.** A snapshot when `LampMarkFilter::EditSerial()` moved (its edit notes: switch, value, move, add, remove), when
  an on state waits, and every 20 frames (edits the filter does not note, or the filter off).
- **Change events.** Each snapshot is set against the last: `added`, `removed`, `switched`, `moved`, `value`.
  `Changes()` holds the last commit's, `LampSerial()` grows at each commit. Developer log: `[RealtimeGI] Lamp change:
  <kind> light=<ptr> lot=<id>`, at most 16 lines a 10 s window; none for the first snapshot of a world.
- **SEH.** The enumeration and each lamp read are in `__try`; a fault adds to `readFaults` (must be 0).
- **Start line.** Logged once in a world, when the active lot is known or after 600 frames there, as
  `[RealtimeGI] On: lots=<n> ...` (pattern of S0-13 unchanged). The active lot is the lot of Apex's registered lamps of
  the active lot (`OutdoorDelta::LotLamps`). `lots=active` gives 0 or 1; `activeAndNeighbours` and `all` count every
  lot with a lamp (`shortcut:` comment: S4-03 adds the neighbour set). Later changes of the count: `[RealtimeGI] Lots: n`
  (developer mode).
- **Counters line** (developer mode, every 10 s) adds `lamps`, `lots`, `lampChanges` and two must-be-0 counters,
  `readFaults` and `lampTableDiffs`.

## Developer test: `debugLampTable`

`[patches.RealtimeGI] debugLampTable = true` with developer mode on: after the first snapshot and after each committed
change (once no on state waits), every lamp of the active lot (every lot lamp while none is known) is logged and checked:

1. read again now against the snapshot: position, every field, on state;
2. against Apex's GPU law (`OwnLotLaw`): position, effective colour (`+0xE0` against `+0xF0 x +0x10` while lit, else 0),
   spot cone (axis, scale, offset), shaded-lamp cones (axis, both offsets, spill) when the law took them;
3. every lamp of Apex's lamp table of the active lot (`OutdoorDelta::LotLamps`) must be in the snapshot.

Summary: `[RealtimeGI] Lamp table: lights=<n> lot=<id> lamps=<n> laws=<n> table=<n> diffs=<n>`; Q2 passes on `diffs=0`.
A differing lamp's line ends with `diff:` and the fields.

## Smoke job `realtime-gi-lamps`

ApexTest-Night, developer mode, `-AB`. The art museum's front lamp off, then on, 9 s apart, paused. The on load expects
the start line, a `Lamp change: switched` line and a `Lamp table: ... diffs=0` line; it fails on a non-zero `diffs`,
`readFaults` or `lampTableDiffs`, and on the enumeration missing. The off load must not log the start line.

## Findings

- Verified (code): `RtOutdoorLamps::WorldLaw` gives a law only for lot lamps (`lot != 0`), so world lights (street
  lamps, lot 0) have no law in the snapshot; their raw fields are there.
- Verified (code): `OutdoorDelta::LotLamps` is filled only while capture and the physical model are on, and it keeps a
  lamp missing from the registry for a short time (`CarryMissing`). With them off the table check has nothing to set
  against (`table=0`) and the active lot stays unknown, so the start line comes after 600 frames with `lots=0`.
- Inferred: right after a lamp is deleted, a carried table entry can show as `not in the snapshot` once. The smoke job
  only switches, so it does not hit this.
- Inferred: a dimmer edit of 0.01 or less is ignored by the game (research 01 section 3), so it makes no event either.
