### WP4: the whole table

The runtime never used the family bits, so the row keeps its 8 bytes. "Every lit family of the census" turned into
"every pixel shader of a technique": a row costs 8 bytes, and blended draws are masked at the draw anyway. Shaders
without a row are now only the 125 `ps_3_0` and 27 `ps_2_0` of the package that no technique uses, mods' shaders and
other game versions.

### WP5: `ps_2_x`

`ps_2_0` has `oC0..oC3`, so no separate wall pass is needed. Its limits and the answers:

| Limit | Answer |
|---|---|
| 12 temps, 64 arithmetic slots in `ps_2_0` | The copy is already `ps_2_x` (Banding Fix, `AddDither2`); the G-buffer part adds 3 temps (game shaders use at most 12) and about 20 instructions |
| 32 constants | 2 more `def`s; refused above 32 (no shader of the package hits it) |
| Arbitrary swizzles need `D3DPS20CAPS_ARBITRARYSWIZZLE` | Not used: the octahedral code was rewritten with replicate swizzles (2 instructions more), for `ps_3_0` too |
| Output registers: written by `mov`, once, all components | The tail builds both values in temps and moves them once |
| Vertex pairing | No change: the G-buffer part needs no pixel position. The grain's `TEXCOORDk` vertex copy is still required for a `ps_2_x` copy, so a draw whose vertex shader cannot carry it stays masked (`ps2NoPair`) |

No `ps_3_0` upgrade is needed: a `ps_3_0` copy would need a `vs_3_0` pair, which the `vs_2_0` game shaders do not have.

### Night Lighting's replacement shaders

Night Lighting draws a replaced shader in a re-issued draw (`lot_light_bridge.cpp`, the only `ReissueScope`): the game's
`SetPixelShader` passes through the hooks (its callback records the game's shader), and the replacement is bound by
`CallOriginalSetPixelShader`. So in a re-issued draw, a bound shader that differs from `CallerPixelShader()` is a
replacement made from that game shader. When the replacement's own hash has no row, the copy takes the game shader's
row (`gb = 3`, counted as `replaced`). The replacement's albedo and probe reads are found by sampler number as usual; a
patch that reads one of them twice gives "albedo unknown" or "no normal" for that shader, not a wrong value.

### Masked writes for unknown shaders: not done

A shader without a row writes "albedo unknown" (id 255), "no normal" and class 3. Masking the draw instead would keep
the values of the surface behind it (or the clear value 0 = static, nothing written) under an opaque object: wrong
albedo, wrong normal, and a static class under an object that may move. The unknown values are the honest answer, and
the work above removes most unknown draws (`unknown=` in the `Scene` line shows what is left). Kept as is.
