## Spec as built

XR-06 already gives the server the depth (INTZ) and a class texture, and runs a pass on the renderer's device in stream
order. The missing piece was the albedo + material id target (G-buffer target 1, `A8R8G8B8`). WP11 adds the smallest
command that puts it on the server's Vulkan device and proves it there:

- `RemixBridge_GiPixelView(src, dst)` (bridge patch 0024): the server blits the renderer's image of `src` into `dst`
  through `ID3D9VkExternalPass::ExecuteExternal`, in stream order, nearest at the same size (the id byte stays exact),
  linear otherwise. Both colour textures; `dst` a render target texture, any format the blit supports.
- It rides on the per-pixel pass's open: it runs only when `RemixBridge_GiPixelOpen` answered on (DXVK with the
  external pass interface and ray queries). shortcut: a renderer without ray queries has no view either; split the
  open when a consumer needs the view without rays.
- Consumers on the server (demodulation for GI accumulation, DLAA / denoisers of research 14 WP14+) bind the same image
  the way XR-06 binds the class texture (sampled in the shader-read layout); the view proves the renderer's image of
  a Direct3D 9 render target is reachable and in the frame's order. Matrices and jitter stay where they are today
  (the pass block), motion and normal targets use the same command when a consumer wants them.

Rejected for this package: a separate compute pipeline for the copy (the blit needs no pass objects, so nothing to
drop at reset); a second command per G-buffer target (one generic texture command covers albedo, normal and motion).
