### WP0: capability line

Once per device, at the first post-scene boundary:

```
[GBuffer] Caps: adapter="<name>" mrt=<n> independentWriteMasks=yes|no mrtPostBlend=yes|no independentBitDepths=yes|no
  ps=<maj>.<min> ps2x temps=<n> slots=<n> A8R8G8B8=rt+blend A2B10G10R10=... G16R16F=... A16B16G16R16F=...
```

(one line in the log). Format values: `rt+blend`, `rt` (render target without post-pixel-shader blending) or `no`.
The `ps2x` numbers are for WP5 (ps_2_x copies). It goes through the device the game holds, so under the bridge it
reports the bridge client's answers, which forward DXVK's (**inferred**: confirmed when the smoke prints it).

Not done from research 14's WP0 row: the "empty RT1 bound during the scene" and its dev view. Binding needs the
target switch tracking of WP3 (unbind at every `SetRenderTarget(0, other)`), so it moved there; doing it twice would
throw away the first version.

### WP1: camera motion vectors

- **Pass:** post-scene effect at order 5 (before Ambient Occlusion), needs the shared INTZ depth bound as the scene's
  depth (the same guard as AO). Writes `mv = current NDC - previous NDC` to a back-buffer-sized `G16R16F` target
  (`D3DPOOL_DEFAULT`, released before Reset, recreated on size change).
- **Math:** `D` is made in double from this frame's and the kept last `PostScene::CameraViewProj` (rows c40..c43) and
  sent as 4 float rows; the shader does `q = D · (ndc.x, ndc.y, d, 1)`, `mv = ndc - q.xy / q.w`. With D3D9 device depth
  `d = clip.z / clip.w`, this needs no near, far or A.
- **Invalid:** 32768 in both channels for the whole frame when there is no camera, no previous camera, or a cut (the
  screen centre at d = 0.99, about 25 m, moved more than 0.3 NDC); per pixel when `q.w <= 0`.
- **View** (`view = 1`): effect at order 35 (after Depth Blur, before Picture's Color): grey = still,
  red / green = x / y motion (0.025 NDC = full), magenta = invalid.
- **Log:** `[GBuffer] On: motion=camera view=<off|motion>` at install, `[GBuffer] Motion pass running: WxH G16R16F,
  view=...` at the first pass, `[GBuffer] Motion: frames=<n> cuts=<n> noCamera=<n> view=...` every 10 s.
- Frames the pass skipped (menus, other depth) keep the last camera: the next vector is against the last frame that
  ran, which is what a history written at that frame needs.

## Plan for WP2 and WP3

### WP2: `AddGBufferPs` for `ps_3_0`, table generator, offline harness (Opus, ~1.5 h, no game)

Scope: the 5 largest `ps_3_0` families: SimSkin 654, Day 498, TerrainHigh 480, Phong 444, Landmark 432.

1. **Generator** `tools/gbuffer_ids/generate.cjs` (pattern: `tools/ao_receiver_test/generate_ids.cjs`, the precomp walk
   of `tools/precomp.cjs` with research 14 §0's render-state list): for each technique pixel shader, the bytecode hash,
   the family, the sampler register named `DiffuseMap` / `colorMap` / `RoadTexture` (albedo, only when read by exactly
   one `texld`), the sampler named `DiffuseLightProbe` / `ExteriorDiffuseLightProbe` (normal source, only when read
   once with a temp coordinate), the material id (about 16 ids from the technique names, fixed priority when a shader
   is shared) and the motion class (Sim*, leaf*, frond, branchMain, Foliage, water = 3). Output
   `shaders/gbuffer_ids.h`, about 8 bytes a shader. SimSkin and TerrainHigh get albedo 255 (family rules are WP10).
2. **Patcher** `ShaderPatches::AddGBufferPs(tokens, info)` in `features/shader_patches.cpp`, beside `AddDither`:
   - refuse the same cases `AddDither` refuses (`DitherResult` reasons) plus "no free temp" and "outputs used";
   - after the albedo `texld`, `mov rA, <dest>`; after the probe `texld`'s coordinate is last written, `mov rN, <coord>`;
   - append after the last instruction (outside any branch): octahedral encode of `normalize(rN)` (~8 slots),
     `mov oC1, rA` with `.a` = id / 255 from a `def`, `mov oC2` = (oct.xy, roughness `def`, class / 3 `def`);
   - with no albedo: `oC1 = (0, 0, 0, 1)` (id 255); with no normal: roughness channel flag "geometric";
   - `oC0` tokens must stay byte-identical.
   - **Merged with the Banding Fix copy:** one entry point applies `AddDither` then `AddGBufferPs` on the same token
     vector, so one copy per shader carries both (no second shader set, research 14 §3.2).
3. **Harness** `tools/gbuffer_check/` (from `tools/banding_fix_check`): every shader of the 5 families through the
   merged patch; each copy created on a native D3D9 HAL device (and with `-D3d9` on DXVK); `oC0` tokens compared;
   counts per family: accepted, albedo found, probe normal found, refused by reason. Disassemble 5 shaders (one per
   family) to confirm the probe coordinate is the world shading normal (research 14 §8).
   - **Pass:** 100% of the 5 families accepted; Day, Phong, Landmark with albedo and probe normal on their candidates;
     SimSkin and TerrainHigh with id 255.

### WP3: bind logic, debug views, counters (Opus, ~1.5 h + 1 game run)

1. **Targets:** `RT1` `A8R8G8B8`, `RT2` `A2B10G10R10` (back-buffer size, `D3DPOOL_DEFAULT`), only when the caps line
   says `mrt >= 3` and both formats are `rt`; otherwise the G-buffer stays off with one log line. Cleared to 0 at the
   first scene draw of the frame. Game MSAA on: off.
2. **Bind in `SceneBinder`** (`features/scene_dither.cpp`, the final draw hook): when it binds a scene draw's copy
   (RT0 = back buffer, depth test on) it also makes sure `RT1..2` are bound; a `SetRenderTarget(0, other)` hook
   unbinds them before the game's call (D3D9 requires equal sizes); the post-scene boundary unbinds them before the
   effects. With the Banding Fix off, the binder runs for the G-buffer alone with the grain constant at 0.
3. **Write masks:** in the render-state hook, `ALPHABLENDENABLE = 1` sets `COLORWRITEENABLE1..2 = 0`, back to `0xF`
   when it goes off (2 calls a toggle). Draws without a patched copy (refused, unknown hash, fixed function) also mask
   both, and are counted.
4. **Debug views** (`[patches.GBuffer] view`): 2 = albedo, 3 = normal (oct decoded, `0.5 + 0.5 n`), 4 = material id
   (hashed colours, 255 = magenta), 5 = motion class (0 grey, 1 green, 2 yellow, 3 red), 6 = stale mask (pixels whose
   draw was masked). Same view effect as WP1, one shader with a mode constant.
5. **Counters** in the 10 s line: patched / refused / masked scene draws, blend toggles, binds, unbinds.
6. **Game run** (one, extend the smoke job with a `variants` list for views 2-5, an F8 picture each on one furnished
   lot): objects coloured by texture, normals change with the surface, UI absent, no trails behind glass or particles;
   the log shows no `SetRenderTarget` size error and the masked-draw count. WP0's "unbound `oC1` write is harmless"
   and fog / sRGB on the extra targets are read from the same pictures.
